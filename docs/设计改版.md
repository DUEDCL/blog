# 设计改版（2026-10-20 起）

> 状态：**方向已定，尚未落地。站里一行样式都没改。**
>
> 这份文档存在的理由：改版的调研、试错与原型的存放位置，如果不写下来，
> 半年后没人知道 `D:\program\dianshi\proto\` 里那几个 html 是干什么的，
> 也没人知道为什么最后选了「满幅影像」而不是「文字即界面」。

## 一、怎么开始的

站主原话两条，按时间顺序：

1. 「我想优化目前的网站排版和 ui 设计……先进行深度调研再对我进行偏好询问」
2. 在四个偏好问题上，四条全部回答「**可完全重做，抛弃报刊设计**」

所以这次不是「精修」，是 **redesign**：旧的四套刊物版次（夜刊/晨版/胶片/霓虹）、
巨大刊名、朱红细压线、竖排栏目标签，都被允许推倒。

## 二、动手前的审计（基于线上真实截图，不是读 CSS 猜的）

当时截了四张：桌面夜刊、桌面晨版、手机 390px、登录页晨版。发现 8 条具体问题：

| # | 问题 |
| :--- | :--- |
| 1 | 顶栏右侧三枚键（登录 / ZH / 版次）重量与站内其它控件不统一 |
| 2 | 手机端导航折成两行，占约 140px，且与刊名之间留白过大 |
| 3 | 首页右栏「随笔」结束后留下大片空白，左右栏严重失衡 |
| 4 | 刊名与右侧题词块关系松散，重量分布不对称 |
| 5 | **登录页与站内语言脱节**：输入框细边、主按钮浅色填充条，像线框稿 |
| 6 | 手机端「问沉麟的分身」浮动按钮压住正文 |
| 7 | 文章列表行只有「标题 ←→ 日期」，缺刊物式元信息，节奏单一 |
| 8 | 晨版下纯白输入框与米白纸面冲突 |

第 1、2、3、5、6 条在后来几轮里已经由小修解决（顶栏账号位、移动端图标化、
两栏节奏、登录页变量化）；**第 4、7、8 条属于版式本身，只有改版能解决。**

## 三、试过的三个方向，以及为什么被否

每一条都做了可交互原型 + 明暗两版 + 手机版，都是真浏览器截图验过的。

| 方向 | 做法 | 站主反馈 |
| :--- | :--- | :--- |
| **A 文字即界面** | 学 [rauno.me](https://rauno.me) 与 [emilkowal.ski](https://emilkowal.ski)：一句话立威、同句内用字重与颜色做层级、条目＝名称＋同行说明、无卡片无图 | 否。太安静，缺冲击力 |
| **B 海报式分栏** | 整幅色带切页、超大序号、正反色交替、悬停整行反色 | 否。仍然「不够有冲击力」 |
| **C 满幅影像 + 产品感** | 真照片满幅当主视觉 + 玻璃浮层 + 真动效 + ⌘K 面板，参照 Arc / Linear | **采纳** |

A 与 B 被否的具体信号（站主多选）：**动效太少、缺一个标志性元素、不够有冲击力、
要以图像为主视觉、要产品感不要文艺风**。这五条合起来指向的不是排版问题，
而是「要一个会动的主视觉」。C 就是照着这五条做的。

## 四、素材这件事（重要，别再踩）

`src/content/photos/` 下的 5 张图**不是照片**，是「渐变底 + 一个圆 + 一个矩形」的抽象占位图，
每张约 10KB、1600×1067 / 1200×1500。所以「以图像为主视觉」这条路，一度被素材卡住。

结论：

- 主视觉用**站主自己生成的一张深蓝夜景**（1672×941，87KB）。**他自产，无版权问题。**
- 落地时要**下载进仓库自托管**（走 Astro 图片管线出 WebP/AVIF），**不要热链**：
  既防外链失效，也保国内速度。
- 分辨率提醒：1672 宽在 1440 屏幕上够，2K/4K 或视网膜放大到全屏会略软。
  可选方案：要一张更大的，或叠一层极轻模糊 + 颗粒盖住。

## 五、硬约束（改版期间站主明确追加的）

1. **音乐状态栏必须沿用原实现**：可拖拽、松手贴边吸附、三态（全展开 / 药丸 / 吸附成封面圆），
   且**默认最小态**（只显示唱片封面）。
   → 曾试过把它做成「固定底部条」，被否。不要在改版里改掉这个交互模型。
2. **问沉麟的分身要有明确的位置与形态**：不能只是一个角落里的小按钮。
   现在的方案是「会呼吸的锥形渐变光球 + 滑出式对话面板」。
3. 图上没有任何注入指令一类的东西（扫过了），可以放心用。

## 八、产品事实（改版必须守住的东西）

改版前用设计技能跑了一遍 `init`，把产品事实固化下来。那份文件（`PRODUCT.md`）站主决定不留在
仓库里，内容并入本节 —— **下面这些不是视觉决策，是前提**，改版可以换掉所有外观，但这些不能动。

**主要读者**（推断，基于三语页面与内容模型）：

1. **读长文的人** —— 从搜索/分享进来，一篇文章读到底。要正文好读、目录清楚、加载快。
2. **回访的熟人** —— 想知道「最近写了什么」。关心时间线与新条目。
3. **站主自己** —— 每天用工具，偶尔进后台改内容。唯一的运维者。

**不面向**：企业采购、招聘方批量筛选、商业客户。所以不需要营销页式的说服结构。

**能力边界**：文章 / 随笔 / 作品 / 音乐 / 图库 / 工具（刷步、影视）/ 问沉麟的分身 /
站点账号 / 机器可读出口（`/rss.xml`、`/sitemap-0.xml`、`/llms.txt`、`/kb.json`）。

**硬约束**：

| 约束 | 含义 |
| :--- | :--- |
| Cloudflare Workers 静态资源 + 一个 Worker | 没有传统服务器；`run_worker_first` 之外的请求不唤起 Worker |
| 国内可直连 | 字体、图片、脚本都不能依赖被墙的 CDN |
| 三语言 | `zh`（无前缀）/ `en` / `ja`，任何新结构都要容纳三种字长 |
| 纯静态 + ClientRouter | 全站 SPA 导航，页面脚本必须能在换页后重新初始化 |
| 对比度有账 | `themes.css` 里逐档标过比值，改版不能松 |
| 不轻易加存储面 | 现有三个 DO（`CHAT` / `APP` / `SITE`）已够 |

## 十、2026-10-21 追加：方向 ①（满幅影像 + 玻璃浮层）已出原型

站主看过第二批 13 例后，只选了 **方向 ①** —— mohamedshehata.net 那一路：一张大图四边出血铺满屏，
导航与联系信息做成浮在它上面的玻璃片。

**原型**：`proto/f-glass.html`（派生自 `e-v5.html`，所以音乐三态播放器 / 分身光球 / ⌘K 三块
招牌**原封不动**，没有重写）。

相对 v5 只动了四处：

1. **顶栏**：整条导航改成一枚悬浮玻璃胶囊（圆角 999px、内部分隔线、末尾一枚实心「名片」按钮），
   不再通栏贴边。滚过首屏仍会落到 is-stuck 的实底态。
2. **首屏**：从「靠下、左对齐」改成「居中」——刊头一句话居中、两枚按钮居中、两侧各一条竖排信息条
   （左：邮件 / GitHub / RSS；右：年份与版本号），底部一条极轻的统计线（文章/随笔/作品/更新）。
3. **CTA 收敛**：三枚收到两枚（实心主 + 玻璃次），第三个入口留给右下角的分身光球。
4. **窄屏收敛**：≤52rem 收掉链接只留刊名 + 搜索 + 名片；≤30rem 再收掉账号位。

已验断点：**1440 / 834 / 390**，均无横向溢出。

**未做**：只有暗版 —— 明暗两套（或四套版次收缩）仍未拍板；文章页、工具页、登录页也未动。

### 踩到的坑：手机截图全是假的

第一轮那批「390px 手机截图」是 **Chrome headless 最小窗口 511px 裁成 390** 的结果 ——
`--window-size=390,844` 在这台机器的 Chrome 上不起作用，最小宽度被钳在 511，
于是所有「手机端溢出/被切」的结论都是假的（一度据此判了 innei 手机端标题溢出，是错的）。

**正确做法**：写一个外层页，把目标页塞进 `width:390px;height:844px` 的 iframe 再截 —
iframe 自己有独立视口，媒体查询按 390 求值。截图见 `duchenlin-blog/preview/refs/m-*.png`。
（站点带 X-Frame-Options 的塞不进去，那两例只能标「未复核」。）

## 十一、2026-10-21 追加：首屏六方案并列（等站主选）

方向 ①（满幅影像 + 玻璃浮层）被站主否掉，理由：**方向本身不对**。三轮被否的共性被判定为
「缺一个真正在动、且只属于这个站的标志物」—— 照片铺底只是"图像主视觉"，动效只是贴在照片上的装饰。

站主表示没有可指认的参考，要求「多做一点我看选」。于是做了并列对照页：

**`proto/g-choose.html`** —— 六种首屏，内容与壳完全一致（同一句刊头、同一套头像导航、
同一个三态播放器、同一个头像分身），只有主视觉与动法不同。按 `1`–`6` 或点底部胶囊切换，
支持 `#v1`…`#v6` 直达，`←/→` 顺序翻。

| # | 名称 | 主视觉 | 动从哪来 | 成本 |
| :-- | :--- | :--- | :--- | :--- |
| 1 | 光场 | 无实体，30 条流动光丝 | canvas 每帧重绘曲线 | 低 |
| 2 | 实体 | 首屏正中一颗环体（分身升级为主角） | CSS 3D 环旋转 + 呼吸 + 鼠标视差 | 中 |
| 3 | 星野 | 头像居中 + 220 颗星 | canvas 粒子 + 鼠标视差 | 低 |
| 4 | 状态机 | 整屏一台仪器：HUD 框 / 扫描线 / 指标列 | 数值跳动、光标闪烁、时钟 | 低 |
| 5 | 图纸 | 制图版：图框、尺寸标注、指北针、引线标注 | 十字光标跟随（动得最克制） | 中 |
| 6 | 巨字 | 两行巨号黑体 | 反色跑马带横穿 + 悬停位移 | 低 |

**构建方式**：`_v.css` / `_v.html` / `_v.js` 是差异部分，由 `%TEMP%\build-choose.cjs`
从 `f-glass.html` 里切出共用壳（tokens / 导航 / 播放器 / 分身 / ⌘K / 旧脚本）拼装成
`g-choose.html`。改完差异部分重跑一次即可，不要手改产物。

### 两个坑（已修）

1. **旧脚本会因为找不到 `#heroMedia` 抛错，把后面的新脚本一起带走** —— 六个方案全部只显示第一屏。
   解法：补一个 `<div id="heroMedia" hidden>`，并把新旧脚本拆成两个 `<script>`，旧的包 try/catch。
2. **截图时 `--force-prefers-reduced-motion` 必须加**，否则入场动画没跑完，截图里正文是空的；
   而且这台机器的 Chrome 写图是**异步**的，必须轮询等文件 >2KB，不能用 `Wait-Process` 卡超时。

## 十二、2026-10-21 追加：方案 7「白熊」（等站主验收）

站主否掉六方案的理由有两条具体的：**头像被裁剪了**（那只白熊的耳朵被圆形裁切切掉）、
**给过的素材一个都没用上**。于是加了方案 7：

- **头像不再裁切**：顶栏与右下分身改为圆角方块瓦片（`border-radius:26~28%`，`contain`），
  熊耳朵完整；方案 3 的居中头像同样改掉。
- **白熊当首屏主角**：`mix-blend-mode:screen` 让黑底消失 —— 图上黑色部分直接透出背景，
  熊完整漂浮，不裁不抠。呼吸浮动 + 鼠标视差（熊会跟着转一点）。
- **素材真正入场**：`hero.jpg` 夜景做底部 38% 氛围带（上缘渐隐）；五张抽象图
  （street-01~03 / quiet-01~02）做慢速漂移的虚化碎片垫在后面，`opacity .17 + blur`。

### 本轮踩的坑

**mix-blend-mode 在有动画的父级上会失效**。熊外面套了一层带 `animation` + `will-change`
的包装，包装自己隔出独立层，混合只发生在层内 → 黑底原样显示成一个黑方块。
解法：把动画、transform、混合模式全部直接落在 `img` 本身，父级只做定位。

局限：熊没法眨眼/眼神跟随 —— 它是一张静态图。想要，需要站主提供分层素材
（眼睛单独一层）或 SVG 版，或者干脆让设计出一只会动的熊。

### 头像适配的关键手法

白熊是**黑底白熊**的方图。暗色模板用 `mix-blend-mode:screen` 让黑底消失；亮色模板
（6、8 右半）用 `filter:invert(1)` + `mix-blend-mode:multiply` 让白底消失、熊变黑。
两头都不抠图、不裁切，耳朵永远完整。屏幕混合还要叠一层 `contrast(1.32)` 把 JPEG 的
近黑噪点压掉，否则熊周围会浮出一个淡淡的方块边界。
