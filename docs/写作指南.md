# 写作指南

## 发一篇新文章

在 `src/content/posts/` 下新建一个 `.md` 文件，文件名就是网址。例如
`src/content/posts/hello-world.md` → `https://duchenlin.top/posts/hello-world`。

文件顶部两条 `---` 之间的部分叫 frontmatter（前置元信息），是这篇文章的元数据：

```markdown
---
title: '文章标题'
description: '一句话摘要，会显示在列表页和搜索结果里'
pubDate: 2026-08-16
tags: ['标签一', '标签二']
draft: true
---

正文从这里开始，用 Markdown 写。
```

## 字段说明

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| `title` | ✓ | 标题 |
| `description` | ✓ | 一句话摘要，用于列表页、社交卡片、搜索结果 |
| `pubDate` | ✓ | 发布日期 |
| `updatedDate` | | 填了会在文章里显示「修订于」 |
| `tags` | | 字符串数组 |
| `draft` | | `true` 表示草稿：本地能看见，构建上线时自动排除。写完删掉这一行或改成 `false` |
| `cover` | | 封面图，如 `'./图片名.jpg'`，图片放同目录 |
| `i18n` | | 标题与摘要的英日译文，见下一节 |

**前三个字段漏了会在构建时立刻报错**，而不是上线后才发现空白 —— 这是内容集合
schema 校验的作用，不是麻烦。

## 让一篇内容出现在英文版和日文版里

站上有三种语言（中文在原地址，英文 `/en/`，日文 `/ja/`）。**什么都不加也不会出错**：
英日两版会照旧生成这一页，标题摘要用中文原文，正文下面挂一条「这篇只有中文原文」。
往上补译文有两级，按你愿意花多少功夫选。

### 一级：只译标题和摘要（多数情况就到这儿）

在 frontmatter 里加一段 `i18n:`，两种语言各一份（只写一种也行，另一种自动回落中文）：

```markdown
---
title: 用 Astro 搭一个不吃灰的个人站
description: 从零到上线的完整记录。
pubDate: 2026-08-16
tags: ['Astro', '前端']
i18n:
  en:
    title: "Building a personal site with Astro that will not gather dust"
    description: "The whole record from nothing to live."
  ja:
    title: "Astro で埃をかぶらない個人サイトを作る"
    description: "ゼロから公開までの記録。"
---
```

这一段管的是列表页、归档、`<title>`、社交卡片、RSS —— 也就是访客在**看到正文之前**
遇到的所有字。值用双引号包起来最省事（英文摘要里的 `:` 不会把 YAML 弄坏）。

**标签不在这里**。标签是索引键，三种语言必须落在同一个键上，否则英文标签页会把
「架构」和 `Architecture` 当成两条。译名集中写在 `src/i18n/*.ts` 的 `tagNames` 里，
一个标签一处；`Astro`、`Python` 这类技术名不必写，查不到就原样显示。

### 二级：正文也译

新建 `src/content/i18n/<语言>/<栏目>/<和原文同名>.md`，比如：

```
src/content/i18n/en/posts/astro-personal-site.md
src/content/i18n/ja/projects/vox.md
```

**路径就是它的身份**，slug 要与原文逐字一致。这个文件是自包含的：标题、摘要写在它
自己的 frontmatter 里（两处都写了以这边为准），正文照常用 Markdown。放进去之后
那一页自动换成译文，标题下那条「只有中文原文」也自动消失 —— 没有别的开关要拨。

译文也认 `draft: true`：本地能看，上线时当作不存在（那一页回落中文原文）。

界面上的字（导航、按钮、页脚、空状态）不在内容里，它们在 `src/i18n/{zh,en,ja}.ts` ——
三份词条表声明成同一个类型，**漏译一条就是一个编译错误**。

## 四个栏目

| 目录 | 栏目 | 特殊字段 |
| :--- | :--- | :--- |
| `src/content/posts/` | 技术文章 | 无 |
| `src/content/notes/` | 随笔 | 无 |
| `src/content/photos/` | 摄影 | `cover` **必填**；`images` 数组放组图 |
| `src/content/projects/` | 作品集 | `status`（`active`/`wip`/`archived`）、`link`、`repo` |

栏目的列表页标题与空状态文案取自 `src/i18n/{zh,en,ja}.ts` 的 `sections`（三种语言
各一份）。`src/consts.ts` 现在只放结构：有哪几个栏目、地址是什么、账号填了没有。

## 摄影相册

```markdown
---
title: 街头
description: 一句话说明
pubDate: 2026-08-16
cover: './01.jpg'
coverAlt: '图片描述，给读屏软件和搜索引擎看'
images:
  - src: './02.jpg'
    alt: '图片描述'
    caption: '图注，选填'
---
```

图片直接放进对应目录即可，构建时自动压缩、转 WebP、生成多种尺寸，**不用手动处理**。

`coverAlt` 和 `alt` 请认真写 —— 读屏软件和搜索引擎只能读到这段文字。

## 支持的写法

- **代码高亮**：三个反引号加语言名，如 ` ```python `。深浅主题自动切换。
- **数学公式**：行内 `$E = mc^2$`，独立成行用 `$$...$$`。
- **表格、任务列表、脚注** 等标准 Markdown 语法。
- 长公式和宽表格会自动横向滚动，不会撑破版心。

## 本地预览

```bash
npm run dev
```

打开 http://localhost:4321。改文件自动刷新，草稿也能看到。

写完确认没问题再构建：

```bash
npm run build
```

构建过不去就是 frontmatter 有问题，报错信息会指出哪个文件哪个字段。
