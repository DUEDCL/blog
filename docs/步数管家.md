# 步数管家（多用户版）

> 2026-10-18 上线。页面：<https://duchenlin.top/bushu>　后台：<https://duchenlin.top/admin>（「用户」「卡密」两个面板）。

## 它是什么

站上的「刷步数」原来是**单人工具**：账号在后台手动加，只有站主自己用。
这一步把它做成了**多用户商用版**：用户注册、绑定自己的 Zepp Life、手动刷步免费、
卡密兑换 VIP、VIP 每天自动补步。两套数据完全分开：

| | 单人工具 | 步数管家 |
| :--- | :--- | :--- |
| 入口 | `/tools/steps`（需登录后台） | `/bushu`（公开，注册即用） |
| 账号 | 后台手动加，无主 | 用户自己注册，每人一个 |
| 存储 | `ChatLog` DO 的 `step_account` | 独立 `AppDB` DO |
| 自动任务 | 每小时扫，条件句全站生效 | VIP 专属，每分钟一批到期任务 |
| 付费 | 无 | 卡密（后台生成，线下收款） |

## 用户流程

1. 注册（邮箱或字母数字账号 + 密码，≥6 位）。
2. 绑定 Zepp Life：填手机号/邮箱与密码，服务端先真登录一次，成功才保存。
   - Zepp Life 里要先「我的 → 第三方接入 → 微信」绑定微信；
   - 新注册、没绑过手环的账号，要先绑一次手环，微信才会同步。
3. 手动刷步：免费，目标 0–98,000 步，每 60 秒 1 次、每天最多 50 次（后台可改）。
4. 卡密兑换 VIP：`/admin → 卡密` 生成，线下收款后发给用户；用户在 `/bushu` 兑换。
5. VIP 自动任务：设定执行时间、阈值、目标区间；系统在设定时间前后错峰执行，
   读今日步数（读不到就用当天已记录值/直接补目标），不足才刷。

## 上限与商业规则

- **用户上限 500**（`AppDB` 配置项 `max_users`，后台「用户」面板可改）。
- 免费：手动刷步不限目标步数，限频率/次数。
- VIP：自动任务 + 手动不限次；天数由卡密决定（30/90/365 天均可）。
- 支付：卡密模式。后台生成卡密 → 用户线下付款 → 发卡 → 用户兑换。
  购买说明可后台配置（默认指向「名片」页）。

## 技术要点

- `src/app-db.ts`：`AppDB`（独立 Durable Object，SQLite）。
  表：`user` / `session` / `account` / `card` / `log` / `cfg` / `rate`。
- `src/app.ts`：公开 API（`/api/app/*`）、自动任务执行器、后台接口。
- `src/pages/bushu.astro` + `src/styles/bushu.css`：用户页。
- `src/worker.ts`：`/api/app/*` 路由、后台挂载、cron 里调用 `appAutoTick`。
- `wrangler.toml`：新增 `APP` DO 绑定与 `[exports.AppDB]`；cron 改为每分钟一次
  （单人版仍在整点跑；多用户版每分钟取 6 个到期账号，避免撞免费档 subrequest 50 的上限）。

### 安全

- 用户密码：PBKDF2-SHA256（2 万次，加盐），只存哈希。
- Zepp 密码：AES-256-GCM 加密后落库，密钥从 `ADMIN_SECRET` 派生。
  **改 `ADMIN_SECRET` 会让已绑定账号解不开**，用户需重新绑定（页面会提示）。
- 会话：随机 token 的 SHA-256 存 `session` 表，cookie `bs_sess` HttpOnly + SameSite=Lax。
- 后台：沿用原 `/api/admin/*` 的登录 cookie；用户管理接口只有后台登录后能打。
- 接口永不回传 Zepp 密码、token、密码哈希；日志只写脱敏信息。

### 已知限制

- Zepp 的读步接口（`GET /v1/data/band_data.json`）2026-10 实测整体返回 400。
  页面「刷新当前步数」会显示上次记录并提示「不是刚读的」；自动任务用当天已记录值兜底。
  刷步写入接口正常，不影响核心功能。
- 自动任务每分钟最多 6 个；用户执行时间会按用户 ID 错峰 0–44 分钟，
  500 人同点也不会挤在一起。
- 微信运动同步由 Zepp Life 决定，通常几分钟；一直不同步时在 Zepp Life 里重新绑微信。

## 本地开发 / 本机跑

```powershell
cd D:\program\duchenlin-blog
npm run build
npx wrangler dev --port 8788
```

- 必须 `build` 之后再起 `wrangler dev`（资源清单在启动时建，见部署文档的已知坑）。
- `wrangler dev` 要读 `.dev.vars`；AI 绑定是远程资源，wrangler 会要求
  `CLOUDFLARE_API_TOKEN`（本机用户级环境变量已设，用 `$env:CLOUDFLARE_API_TOKEN` 取）。
- 本机验证：

```powershell
curl.exe -s http://127.0.0.1:8788/api/app/state
```

本机跑适合开发与验收；线上仍是 Cloudflare Worker（域名、证书、定时器都在那），
不建议把 500 人的服务挂在家用电脑上（断电、IP 变动、备案主体都不合适）。
