# 技术架构

## 选型与理由

| 层面 | 选择 | 为什么 |
| :--- | :--- | :--- |
| 站点框架 | Astro 7 | 默认零 JS 输出，博客这类内容站首屏最快；内容集合（Content Layer）带类型校验，frontmatter 写错在构建时就报错，不会上线后才发现空白 |
| 内容格式 | Markdown / MDX | 纯文本、可版本控制、不锁定平台 |
| 托管 | Cloudflare Workers 静态资源模式 | 不是 Pages。裸域绑定、证书、CDN 一体，免费额度足够个人站。**2026-08-22 起同一个 Worker 还带一条 `main`**，见下「服务端」一节 |
| 图片 | Astro 内置 `sharp` | 构建时压缩、转 WebP、生成多尺寸，写作时不用手工处理图片 |
| 代码高亮 | Shiki 单主题（`github-dark`） | 构建时高亮，运行时零成本。R31 砍掉浅色主题后从双主题改回单主题：双主题只会让每个 code 块多带一份用不上的 `--shiki-light-*` |
| 数学公式 | KaTeX + remark-math | 比 MathJax 轻，样式与字体自托管 |
| 部署工具 | Wrangler | 本地一条命令部署，不依赖 CI |

## 硬约束

**不引用任何境外 CDN 资源。** 站点托管在境外，国内访问时请求数比字节数更影响首屏。
所以：

- 西文字体（Fraunces 可变字体 / IBM Plex Mono）随构建产物分发；
- 中文**不加载任何字体**，走系统字体栈（零加载成本，这是中文站最大的性能杠杆）；
- KaTeX 的样式与字体自托管；
- 后续加任何第三方能力，先确认能否构建时内联或自托管。

**`npm run build` 不只是 `astro build`**（R41 起）：它先跑 `scripts/gen-content.mjs`，
把 `src/content/` 下的原始 Markdown 打成 `src/data/content.generated.ts`，
供 Worker 在 `/api/admin/content` 里读 —— 后台的「文章编辑」与「图库管理」靠它看到仓库内容。
那个文件在 `.gitignore` 里（派生物），所以**部署前必须跑过一次 build**，
否则 `wrangler deploy` 会因为找不到这个 import 而失败（会明确报错，不会静默上错代码）。

## 服务端：`/api/music/*`（点歌台）

本站原先没有一行服务端代码。**2026-08-22 起 `wrangler.toml` 有了 `main = "src/worker.ts"`** ——
这道「单向门」第 11 轮已批准，由 [R11 点歌台](需求台账.md#r11-点歌台-) 提前走完。

```
GET /api/music/list?id=<白名单榜单 id>            → { items: JukeTrack[] }
GET /api/music/search?q=<关键词>&n=<1..30>        → { items: JukeTrack[] }
GET /api/music/url?id=&source=&sign=[&name=&artist=]
                                                  → { url, bytes?, swapped?, short? }
GET /api/music/lyric?id=&song=&source=&sign=      → { lyric, tlyric }
GET /api/music/pic?id=<pic_id>&song=&source=&sign= → { url }        ← R22 加的封面
```

四个要点：

- **只有这五条进 Worker**。`run_worker_first = [ "/api/music/*" ]`，其余请求连 Worker 都不唤起
  （省调用数，也少一个故障点）。即便如此，`fetch` 的第一行仍然兜一道：路径不以 `/api/music/`
  开头就 `return env.ASSETS.fetch(request)` —— 官方文档没写清 `not_found_handling = "404-page"`
  与「数组之外的路径是否仍进 Worker」的优先顺序，不赌。
- **Worker 只中转 JSON，音频字节不经过它。** 这是容量前提：直链是 https、
  `Access-Control-Allow-Origin: *`、支持 Range，浏览器直接从 `music.126.net` 拉，一首歌
  13 MB 一个字节都不进 Worker 配额；Worker 转的只是几百字节到几十 KB 的 JSON。
  **不要改成中转音频。**
- **出口只吐白名单字段**（`JukeTrack`），不原样转发上游 JSON；上游的响应体与错误页一个字都不
  外泄，返回给访客的全是自己写的中文。榜单 id 同样是白名单，否则这就是个「任给 id 就拉网易云
  歌单」的公开代理。
- **缓存头在代码里自设** —— `public/_headers` 不作用于 Worker 生成的响应，边缘缓存显式走
  `caches.default`（Workers 独有的默认缓存区）。逐端点的值见
  [部署运维 · 缓存](部署运维.md#缓存)。

上游契约（`yinyueku.cn/api.php` 的参数表、签名怎么绑 `types`、四条踩过的坑）全部记在
`src/data/jukebox.ts` 的顶部注释里 —— 那是全项目唯一记录它的地方，改 `worker.ts` 之前先看它。

**刻意不引 `@cloudflare/workers-types`**：它的全局 `Request`/`Response` 会和 Astro 的
`lib.dom` 打架，为一个 `Fetcher` 类型换来全站类型冲突不值得。用得到的绑定就地声明成
`interface Env { ASSETS: { fetch(req: Request): Promise<Response> } }` 即可。

**`url` 端点带 `name` 时会「择优选源」**（R14 加的）：上游同一次搜索的候选里，完整版与几十秒的
片段是并排的，取第一条就会随机地播到片段 —— 表现出来就像「VIP 歌播不全」。所以传了 `name` 时
它先用 `Range: bytes=0-9` 探首选有多少字节，偏小（< 2 MB）才并发去 netease + tencent 搜同名候选、
逐条探头、返回最大的那条，并附 `swapped` / `short` 标记。**不传 `name` 的行为与这个改动之前
一字不差**，老前端不会被打断。细节与实测证据见 [R14](需求台账.md#r14-唱片机翻修跨页不间断逐字歌词择优选源起始页当门面-)。

**`pic` 端点与封面链路**（R22 加的）：唱片中心标签贴的是专辑封面，本地那首用 `public/audio/`
里的文件，点歌进来的曲目走这条链 —— `toJuke()` 多取一个 `pic_id`（**不进必填校验**：没有封面
照样能播，不能因为缺它把整条候选判死），前端只在某一首**真的要播**时才 `void loadPic(i)`，
与 `loadLyric` 并列。列表接口一个字不改，所以一屏 30 条搜索结果不会变成 30 次上游往返。
`pic` 与 `lyric` 同一个坑：**歌曲 id 算进签名校验**，漏了 `song` 上游会回
`{"url":"签名错误！"}`（HTTP 200、合法 JSON、字段名也对），所以 Worker 校验的是**内容**——
不以 `https://` 开头就 502。封面字节同样不经过 Worker（直链自带一年缓存与 `acao: *`）。

**加了 `main` 的代价**：以前构建失败只是不部署、线上不受影响；现在 Worker 抛异常就是线上 500。
所以每条路径都有兜底，`route()` 的异常统一落到 502 加一句人话。

## 服务端：`/api/admin/*`（后台）

R41 起后台是五个面板：模型 / 聊天记录 / 聊天实时接管 / 文章编辑 / 图库管理。
接口一览（**全部要求登录**，只有 `state` 未登录也能打，那时它只回两个布尔值）：

```
POST /api/admin/login | logout                     → 签名 cookie，7 天
GET  /api/admin/state                              → 线路（密钥只报有无）、停服开关、lastWhy
GET  /api/admin/stat                               → 顶栏那几个实时数字，一次问完
GET  /api/admin/sessions                           → 会话索引（带「接管中／有人在等」）
GET  /api/admin/log?session=&after=                → 某会话的消息，`after` 供增量轮询
GET  /api/admin/content[?path=|?coll=]             → 仓库内容（目录 / 单份 / 整个集合）
GET  /api/admin/drafts | draft?id=                 → 后台草稿
GET  /api/admin/reach?base=&proto=[&key=]          → 可达性探测（目标 + 两个对照，并行）
GET  /api/admin/models?base=&proto=[&key=]         → 拉这家的模型列表
POST /api/admin/save                               → 存线路数组与停服开关
POST /api/admin/test                               → 打一次上游（`raw: true` 走不解析通道）
POST /api/admin/takeover                           → 人工接管的开关
POST /api/admin/reply {session,text,tab}           → 发一句人工消息（tab = 发给哪个窗口）
POST /api/admin/draft-save | draft-del             → 草稿增删
```

### 访客侧那两条通道（R43）

`/api/chat` 一个路径两种方法，这不是图省事 —— `wrangler.toml` 的 `run_worker_first`
列的是**精确路径**，新开 `/api/chat/listen` 就压根不进 Worker（当静态资源，直接 404）。

| | 做什么 |
| :--- | :--- |
| `POST /api/chat` | 发一句话，回一段 SSE（模型的字，或接管时沉麟打的字） |
| `GET /api/chat?tab=&after=` | **主动接收**：挂最多 25 秒等人工消息。`after=-1` 只取游标不回放 |

GET 那一条是 R43 补的，起因是他问「为什么接管后不能主动发送消息」：
R41／R42 的接管是**应答式**的（访客问一句才有一条请求挂着），访客那边没有常驻通道，
所以「没人发问时」沉麟打的字没地方送，还会因为取不到收件人而落成 `tab` 为空的死信。

三条不能省的约束（每一条都有具体的失败在背后，详见 [台账 R43](需求台账.md)）：
游标存 `sessionStorage` 且首次不回放；访客发问时**两侧各掐一次**那条 listen
（前端 `AbortController` + DO 的 `/wait` 踢掉同窗口的 listen，否则一句话出两条气泡）；
空转 40 轮（约 17 分钟）停下，免得被遗忘的标签页一直烧 DO 的 duration 配额。

### 会话＝一个 IP，窗口＝一个标签页（R42）

**会话号在服务端按 IP 派生**：`SHA-256('ip:' + <cf-connecting-ip>)` 取前 16 字节，
32 个十六进制字符，正好落在 `SESSION_RE` 里。前端传什么都不作为会话号采信 ——
它不知道自己的 IP，而它自己生成的那个 uuid 是「一个标签页一份、关掉就换新的」。
取 hash 不是为了保密（IPv4 能枚举），是不让 IP 出现在 DO 实例名与日志里；
**不加盐**是刻意的 —— 加了就与某个 secret 绑死，那个 secret 一换所有历史集体失联。

那个 uuid 降级成**窗口号**（`msg.tab`），因为一个 IP 后面可能有好几个人
（NAT、手机 CGNAT）。两层的分工：

| 层 | 管什么 |
| :--- | :--- |
| 会话（IP） | 后台看到几条线；接管开关按它挂；同一个人刷新／换标签／关掉再回来都是这一条 |
| 窗口（tab） | `/history` 只取同一个窗口 → 上下文不串；`/wait` 与 `/reply` 按窗口配对 → 接管的回复不发错人 |

拿不到 IP 时（`wrangler dev` 下就没有这个头，实测确认）退回用窗口号当会话号，
与 R41 的行为一致。老前端发的是 `{session, …}`，当窗口号收下 —— HTML 有 7 天 SWR，
那些页面最多还能活一周。

### 人工接管：访客那一侧是零延迟的

接管开着时 `/api/chat` 不调模型，而是让访客那条请求**挂在服务端等**。
挂起不是轮询：Durable Object 在内存里存着一组回调（`#waiters`），
沉麟在后台按发送走 `/reply`，就地把那条请求放走。同一个会话号永远落在同一个 DO 实例上，
所以两头一定见得到同一个 Set —— 这正是当初选 DO 而不是 D1 的理由（存与推是同一个对象）。

四条硬规则，每一条都有具体的失败在背后：

| 规则 | 不这么做会怎样 |
| :--- | :--- |
| 访客那句 **`await`** 落库，不用 `waitUntil` | 后台看不到那句话就没得可回；DO 判断「有没有新的人工回复」的锚点也就是它 |
| 25 秒超时**退回模型** | 访客不知道有接管这回事，他等了 25 秒该拿到一个回答 |
| 只在「他此刻开着那一页」时生效（cfg 的 `seen`，90 秒容忍） | 接管开着而他去睡了 → 之后每个访客的每一句都先白等 25 秒 |
| 回复切成 24 字符／40 ms 逐段发（`textStream`） | 一次吐完会「啪」地整段出现，节奏与模型回答不一样，访客看得出来 |
| `/reply` 只放走**最近一个开始等的窗口**（R42） | 会话按 IP 合并了，同一条会话下可能有两个人同时挂着 —— 一句话发给所有人是错的 |

落库时人工那句标 `who = 'human'`（列名用 `who` 不用 `by` —— `BY` 在 SQLite 关键字表里），
`role` 仍是 `ai`：喂给模型当历史时它必须算 assistant，否则下一轮模型会以为自己没说过话。

### 上游线路是一串，不是一条（R41③）

`Cfg.routes` 最多三条，**按顺序试**：每条线路的每个候选模型挨个试，全挂了才掉 Workers AI 兜底。
国内服务商从 Cloudflare 的境外边缘打过去不保证通，一条线路的配置下赌错就是功能停摆。

两个容易写错的点：

- **解析器要跟着线路走**。三条线路可以各配不同协议，出字那条的 `shape` 必须是它自己的 ——
  拿错协议的表现是「HTTP 200 但一个字都抽不出来」。
- **密钥按位置沿用**。前端永远收不到密钥（`state` 只报有无），所以保存时留空＝沿用同一位置
  原来那把。重排线路顺序时密钥会跟着位置走，不跟着服务商走。

配置存在 DO 的 cfg 表里（`routes` 一个 JSON）；解析失败或为空时回落到 R39 的老键与
三个 secret（`CHAT_BASE`/`CHAT_KEY`/`CHAT_MODEL`）—— 所以线上部署完的那一刻行为不变。

## 全站 SPA 路由与那个不会停的播放器

**2026-08-22 起本站不再是「一堆各自独立的静态页」** —— `BaseLayout.astro` 里加了
`<ClientRouter />`（Astro 的 View Transitions），全站换页走 SPA。唯一的动机是那条需求：
「我的网站其他地方正在播放的音乐不会停止」。localStorage 存进度再续播做不到 —— 声音会有裂口。

```
BaseLayout.astro          ← 正站所有页面
  <ClientRouter />
  <MiniPlayer />          ← 内含 transition:persist="jk"

pages/index.astro（门）    ← 不走 BaseLayout，所以这三样手工各加一份：
  <ClientRouter /> + <MiniPlayer /> + <ThemeBoot />
```

播放器的状态机在 `src/scripts/jukebox.ts` 的单例闭包里（队列、当前曲、播放方式、歌词、rAF、
`WordRun`）—— bundled module script 全站只执行一次，所以它天然跨导航存活。`/music` 的唱盘台与
`MiniPlayer` 的状态栏都只是它的**视图**，读同一份状态，所以两处显示的必然是同一首歌、同一档播放方式。

**这套东西有五条不写下来就会再踩的规则：**

1. **`<audio>` 必须挪到 `<html>` 底下。** Astro 7.2.x（含 7.2.4）的 `reifyMediaElements` 会**无条件**
   把新 body 里所有 `audio`/`video` 换成克隆，而且这一步排在「搬回 persist 节点」之后、没有豁免 ——
   正在播的那个 `<audio>` 会被换掉、脱离 document、按规范跑 internal pause steps。
   `document.documentElement.appendChild(au)` 站到它的扫描范围之外，这是整套机制的命门。
   上游 main 已修（按节点身份豁免）但未发布，升级躲不过去。
2. **状态栏的根节点必须每页都渲染。** persist 靠名字配对，目标页面没有同名节点就不搬、
   老节点连着旧 body 一起丢。所以「不显示」只能用 `hidden`（门就是这么藏的），不能不渲染。
3. **顶层 `querySelector` 的引用导航后作废。** module script 只跑一次，新文档的节点没被绑过。
   DOM 相关的绑定要放进 `astro:page-load`（首屏与每次导航都触发）；
   而 window/document 上的监听**必须**留在模块顶层，放进 `page-load` 会每导航累积一层。
4. **`<html>` 上的属性每次 swap 都会丢。** `swapRootAttributes` 先把现有属性全删再套新文档的，
   所以 `data-theme`、`data-js`、`data-jk`、`--jk-room` 这些运行期写的东西都要在
   `astro:after-swap`（换页后、paint 前）重设。`ThemeBoot.astro` 就是干这个的。
5. **`location.href = …` 是硬导航，会掐断音频。** 站内跳转用 `astro:transitions/client` 的
   `navigate()`。门的「进入」踩过这个。

`ThemeBoot.astro` 之所以抽成组件而不是两处各抄一份：Astro 按**脚本 `textContent` 逐字**去重，
两处一模一样才会被认成同一段、只跑一次、只挂一个监听。差一个字符就各跑一次。

`player.css` 也是这套改造的产物 —— 播放器的 DOM 是 JS 造的，而 Astro 的 scoped CSS 编译成
`data-astro-cid-*` 属性选择器，动态节点没有那个属性，样式全部落空（表现为「榜单有白色打底」
「歌词前面有 17. 18. 19.」）。跨页播放本来就要求播放器脱离单页作用域，所以这些样式最终必须是全局的。

**它由 `MiniPlayer.astro` import，不由 BaseLayout**（R22④ 挪的）。门不走 BaseLayout，而 R22④ 要
状态栏在门上也露脸 —— 样式跟着它唯一的必需视图走，凡渲染状态栏的页面就一定有它，顺带消灭
「某一页忘了 import」这个故障模式（`/music` 的舞台样式也在这份文件里，而它走 BaseLayout →
一定渲染状态栏 → 一定有）。

## 设计系统

全部集中在 `src/styles/global.css`，靠 CSS 自定义属性（CSS 变量）分层。改视觉只改变量，
不碰组件。唯一的例外是 `src/styles/player.css` —— 播放器的样式必须是全局的（原因见上一节末），
它只用 `global.css` 的令牌，**只有一处例外**：末尾那个 `[data-portal] .jk-mini` 块就地钉了一份
深色档令牌，因为门（起始页）是全站唯一不引 `global.css` 的页面，状态栏在那儿否则
拿不到任何令牌。选择器落在 `.jk-mini` 上而不是 `[data-portal]` 上 —— 那面旗挂在 `<body>`，
写在 body 上的 `--ink` 会赢过门 `:root` 里的 `--ink: #fbfbfb`（门洞白光），把题词一起改色。
**改 `global.css` 的 `--glass-*` / `--sand-*` 时那一份拷贝要跟着改。**

### 分层

1. **令牌层** `:root` —— 字体、字号、间距（8px 基准）、版心宽度、圆角、颜色、玻璃参数、光晕。
2. **主题层** `:root[data-theme='light']` —— 只覆盖颜色相关令牌。
3. **基础层** —— 重置、排版、链接、滚动条。
4. **工具层** —— `.wrap`（版心）、`.glass`（玻璃面板）、`.meta`、`.vertical-label`、`.rise`（淡入）。
5. **正文层** `.prose` —— Markdown 渲染结果的排版。

### 毛玻璃的三个物理前提

这套效果做不出来时，问题基本都在这三条上：

1. **必须有可折射的底层。** `backdrop-filter` 在纯色背景上完全看不出效果。
   `body::before` 铺的三团径向渐变光晕就是折射源，它是物理基础不是装饰。

2. **光晕层不能溢出视口。** 必须 `position: fixed; inset: 0`。径向渐变的中心写的是百分比，
   按元素盒子解析 —— 元素一旦比视口大，中心就被按比例推到视口外，屏幕上只剩边角余晖。
   **踩过一次。**

3. **`body` 不能有不透明背景色。** `body` 只有 `position: relative`、`z-index: auto`，
   不构成层叠上下文，所以两个负 `z-index` 伪元素落到根（`html`）层叠上下文里。
   在根上下文中负 `z-index` 后代先绘制、`body` 自身背景后绘制 —— `body` 一旦有不透明背景
   就会把光晕层和颗粒层整个盖掉。**底色交给 `html` 承担。**

### 玻璃的构造只有深色这一档（R31）

站主 2026-08-24 的原话是「彻底砍掉浅色状态，只保留目前的黑色状态（切换按钮也删了）」，
于是这一节从「两档构造对照表」缩成一句：**玻璃本体是白色半透明提亮，外描边也用白色半透明
（白压深底本来就看得见），内高光只要一道轻微的 `inset` 白线，底色越深越好 —— 它是衬托光晕的。**

为什么值得留一句：浅色档当年的坑正是「照抄深色的构造」——
白描边压在浅底上等于没有描边（详见 [需求台账 R4](需求台账.md#r4-浅色主题下玻璃不明显-)）。
将来若有人想再加一档浅色，先读那一条，别再从深色抄一遍。

### 中文排版决策

- 正文 `17px`（中文舒适下限）、行高 `1.85`（中文比西文需要更大行高）、字距 `0.01em`。
- 文章版心 `38rem`，每行约 33–36 字。
- 标题西文用 Fraunces 衬线、中文落宋体栈 —— 中文编辑排版的经典对比手法。
- 正文中文用黑体栈（屏幕上比宋体耐读）。
- `.prose strong` 用强调色而非加粗：中文没有真正的粗体字形，加粗靠合成，效果差。
- 元信息用等宽 + 全大写 + 宽字距，编辑感的来源。
- `.vertical-label` 竖排中文栏目标识，仅宽屏显示 —— 本站的记忆点。

### 只有深色，没有切换（R31）

`:root` 里一套色板、`color-scheme: dark` 一处定妆，**不读 `prefers-color-scheme`、
没有 `[data-theme]` 选择器、顶栏也没有切换键**（`ThemeToggle.astro` 已删）。

`ThemeBoot.astro` 留着，但只剩一件事：写 `<html data-js>`（`/music` 靠它决定露唱片机还是
原生 `<audio>`），并挂 `astro:after-swap` 重设 —— SPA 换页会把 `<html>` 的属性清光
（见上一节第 4 条）。用它的仍是两处：`BaseHead.astro`（正站）与 `pages/index.astro`
（门，它不走 BaseLayout），两份必须逐字相同，否则 Astro 的脚本去重会让它跑两次。

`localStorage['theme']` 那个旧键不再有人读，也没有清除逻辑 —— 留着不影响任何行为。

### 状态栏与页脚抢地方：`--jk-room`

状态栏 `position: fixed`、不占布局流，滚到页面最底时会压住页脚那行链接。补法是让它**现量自己的
高度**写成 `<html>` 上的 `--jk-room`（`data-jk` 是开关），`player.css` 里
`[data-jk] body { padding-bottom: calc(var(--jk-room, 0px) + var(--sp-6) * 2) }` —— 不挪任何元素，
只把可滚区域往下拉长一截。加在 `body` 而不是 `.site-footer`：后者与 Footer 自己那条 scoped 规则
特指度打平（都是 0,2,0），谁赢看样式表顺序。

**R25 起判据是「状态栏是不是真的压着底部」**（`rect.bottom > innerHeight - 24`），不再是
「显不显示」—— 因为它现在能被长按拖到任意一条边，拖到顶上之后再给页脚让位就是白留一段空白。

### 状态栏的三个形态与长按拖动（R25 / R27 / R28）

**三个形态**，全靠根节点上的两个类区分（R28 定的）：

| 形态 | 类 | 里面有什么 |
| :--- | :--- | :--- |
| 全展开 | 无 | 封面、曲名、歌手·专辑、歌词、进度条、四个键、**音量** |
| 药丸 | `.is-fold` | 封面、曲名、歌词、上一首·播放·下一首（**默认就是这个**） |
| 吸附 | `.is-dock` | 只有一枚 48px 的封面圆 |

前两态由 head 右侧那枚 ⌃/⌄ 键（点封面也行）互切并存进 `localStorage`；第三态只能由
**长按拖到左右竖边**进入，**不落盘** —— 换页或刷新时 `reflow()` 撤掉它，回到前两态。
`.is-dock` 的规则排在 `.is-fold` 之后、也排在 `.is-placed` 的宽度声明之后：三者特异度相同
（都是 0,2,0），全靠源码顺序取胜，挪动它们就会互相压掉。
音量用的是与 `/music` 唱盘台**同一个** `data-vol` 契约与 `setVol`，两处调的是同一份状态。

**长按拖动**：按住 **200ms** 进入（R29 从 450ms 降下来的，站主嫌不跟手；期间移动超过 8px
当滑动、取消），松手吸到最近的一条边。门限这么短，就必须配一条**原地松手视为点击**
（位移 < 6px 时整件事作废、不吸边也不吞那一下 click），否则「按得稍久的一次点击」会被算成拖动，
点封面就再也切不了形态。吸到**竖边**时贴边距离是 **0**（吸附态就该贴死，R29 站主说「没有很贴」），
其余边仍留 16px；吸附那一下的圆心用**最后的指针位置**而不是卡片中心 ——
卡片从 208px 收成 50px 的圆，拿中心当锚点会让圆停在离手指几十像素外（实测偏 63px）。
位置存的是**「贴哪条边 + 沿边的比例」而不是像素** —— 转屏与改窗口大小都不会把它甩到屏外。
两把键：正站 `music:pos`、门上 `music:pos:portal`（门是满屏画面，合适的位置本来不同）。
折叠态同样分两把：`music:mini` / `music:mini:portal`，没存过时门上与窄屏正站都默认药丸。
长歌名装不下时在固定框里跑马灯，溢出量由脚本量出来写进 `--jk-over`。

**三条踩过的坑，改之前先看**：

1. **`touch-action: none` 必须常设在 `.jk-mini__card` 上**，不能只在拖动时加 —— 它在手指
   落下那一刻就求值了，默认的 `auto` 会让浏览器把上下方向的移动判成滚页面并发
   `pointercancel`，表现就是「药丸只能左右小幅动、上下动不了」（R27 报上来的正是这个）。
2. **量尺寸之前先挂 `.is-placed`，而且别在 `hidden` 时量**：那条规则自己带宽度，量早了会
   拿旧宽度算边距（右边那一档会算到左边去）；藏着时 `offsetWidth` 是 0，算出来的坐标直接
   把它顶到屏幕外。`show()` 在「藏↔露」翻转那一刻补算一次。
3. **拖动的收尾要有兜底**：`pointerup` 不一定来（切标签、系统手势、指针捕获被静默收走），
   所以 `blur` 与 `visibilitychange` 也接到 `endDrag`；「吞掉拖完那一下 click」的旗子要
   自动复位（400ms），否则它一直举着，会把用户下一次真正的点击也吞掉。

默认位置由 CSS 给（门上水平居中、贴底，R27 定的「中间下部」），脚本只在用户拖过之后用
`.jk-mini.is-placed`
覆盖 —— **那条规则必须留在 `player.css` 最末尾**：它与 `[data-portal] .jk-mini` 特异度相同
（都是 0,2,0），靠源码顺序取胜，挪到前面门上就再也拖不动了。

## 内容模型

四个集合定义在 `src/content.config.ts`，共用字段 `title`、`description`、`pubDate`
（必填，缺了构建报错）、`updatedDate`、`tags`、`draft`、`cover`。

`photos` 额外要求 `cover`，并支持 `images` 数组放组图；`projects` 额外有
`status`（active/wip/archived）、`link`、`repo`。

草稿（`draft: true`）本地可见，构建时排除 —— 过滤逻辑在 `src/utils/content.ts`。

写作字段的完整说明见 [写作指南](写作指南.md)。
