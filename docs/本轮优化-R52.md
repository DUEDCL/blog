## 1. 登录界面「信息显示不完全」——根因是 SPA 换页不重跑内联脚本

**现象**：有时正常，有时整页只剩标题，表单与「当前账号」都不出现。

**根因**（可复现）：全站走 ClientRouter，而 Astro 对 `is:inline` 脚本的默认行为是
**只在首次加载时执行一次**。从别的页面点进 `/login` 时那段脚本压根不跑，两块面板
（`data-panel="form"` / `data-panel="me"`）都停在模板的 `hidden` 上 —— 于是什么都看不见。
直接刷新 `/login` 反而正常，所以症状是「经常」而不是「总是」。

**修法**（两半，都要）：
1. `<script is:inline data-astro-rerun>` + 入口挂 `astro:page-load`，并保留
   `data-ready` 守卫防重复绑定；
2. **表单在模板里默认可见**（去掉 `hidden`），JS 只在确认已登录后才换成账号面板 ——
   接口慢、脚本没跑、JS 被禁用，看到的都是一个能用的登录表单。

顺带：账号名 `overflow-wrap: anywhere`（窄屏不再被挤出卡片）、窄屏内边距收一档。

## 2. 「影视聚合」→「沉麟看剧」，以及播放体验的整体重做

页面标题、页头、工具目录卡、`<title>`/`description`/`footerNote` 全部改名；
路由仍是 `/tv`（改名不改地址，已有链接与书签不受影响）。

### 2.1 多用户共享记录 —— 本地键按用户分域

**根因**：`localStorage` 的 `tv:q` / `tv:prog` 是**全浏览器共享**的，与登录用户无关。
同一台电脑换个人登录，看到的还是上一个人的搜索词与进度。

**修法**：`SCOPED = {q, prog, fav}` 三个键在读写时拼上用户 id（`tv:prog:<userId>`）。
进入页面先问 `/api/site/me` 拿到 id 再读记录；**旧的无主键会被迁移到当前用户名下然后删掉**
（不删的话换个人登录仍然看得到）。匿名访客照旧用无后缀的键，互不影响。
云端那份本来就是按 `user_id` 存的（`SITE` DO 的 `tv_q` / `tv_prog`），没有改动。

### 2.2 长按右箭头：有时失效、有时直接快进

**两个现象一个根因**：长按根本没有落在我们的手势上。
- 「直接快进」：按住的是浏览器原生控件（或 `<video>` 有焦点时的方向键），原生行为就是 +5s，
  冒泡阶段的 `keydown` 拦不住；
- 「失效」：`keyup` 丢在窗口外（切标签、松手时焦点不在文档里），`holdingBoost` 卡在 true，
  之后再也不进加速分支。

**修法**：
1. 屏幕上的 **⏭ 键变成「点按下一集 / 长按加速」**（pointerdown 起 280ms 计时器，
   pointerup/pointercancel/pointerleave 收尾，捕获阶段吞掉长按后的那次 click）；
2. 键盘走 **capture 阶段** `preventDefault`，抢在原生控件之前；
3. 三条兜底复位：`blur`、`visibilitychange`、换集/换源时清零。

### 2.3 多播放源管理：只留最优、藏掉播不了的

- 详情页**默认只显示一条源**（探测出来的最优那条），其余收进「换源（还有 N 个）」；
  手动选完自动收回。
- **`kind === 'page'` 的线路（资源站网页播放器地址）默认不显示**，收进
  「显示 N 条无法直连的线路」；全部都不能直连时才照旧全列，避免抽屉空着。
- 当前停在一条播不了的线路上、又有能播的，自动挪到第一条能播的。

### 2.4 追剧收藏

- 存储：`SITE` DO 新表 `tv_fav`（`user_id + 片名` 主键），接口走既有的
  `/api/tv/hist`（GET 一次带回搜索词/进度/收藏；POST 支持 `{fav}` 与 `{unfav}`）；
  未登录时落 `localStorage`，登录后按 `ts` 合并。
- 入口：海报左上角 ☆、详情页「☆ 追剧」、首页「我的追剧」区块（可一键取消）。
- 收藏里存的是**最后一次看的位置**（源 id / 线路名 / 集名 / 秒数），所以「继续看」不用再搜。

### 2.5 点播放记录 → 直接回到上次那一秒

原来是「填关键词 → 重新搜全网 → 找同名分组」，既慢又会因源站抖动而找不到。

现在 `openByRecord(rec)`：拿记录里的 `srcId + vodId` 直接问 `/api/tv/detail`，
拼一个单候选分组，**按线路名**（不是下标，源站重排线路时下标会变）定位线路、
按集名定位剧集，直接起播；`resumeIfAny()` 照旧把 `currentTime` 跳到记录里的秒数。
只有 detail 失败（源挂了、片下架）才退回搜索 —— 那是退路，不是主路。

### 2.6 清晰度：能提的都提了，提不了的写清楚

| 手段 | 做了什么 | 依据 |
| :--- | :--- | :--- |
| 码率上限 | `capLevelToPlayerSize: false` | 默认 true 会把码率压到播放器像素尺寸，手机小窗等于主动降画质 |
| 起播档位 | `abrEwmaDefaultEstimate: 8Mbps` | 默认 500kbps 会让第一段挑最烂的档再慢慢爬 |
| 锁最高档 | `autoLevelCapping = 最高档` + `currentLevel = 最高档`（「画质优先」默认开） | ABR 想降也降不下去 —— 这是「看着看着变糊」的根因 |
| 缓冲 | `maxBufferLength 45` / `maxMaxBufferLength 300` / `backBufferLength 60` | 网速抖一下不立刻触发降档 |
| 选源 | 探测前 10 个候选，分辨率压倒一切，同分辨率再比码率与延迟 | 既有逻辑，未改 |
| 观感 | 「增强」开关：`contrast(1.06) saturate(1.06) brightness(1.02)` | **不改变实际分辨率**，只改善低码率片源的灰蒙观感 |

**「真 4K / 超分」为什么不做的**：MoonTVPlus 的「视频超分」是 WASM/WebGL 逐帧推理，
需要把解码后的每一帧搬进 GPU 再搬回来。免费档 Worker 与手机都吃不消，而且片源本身
最高只有 1080p（96 条记录实测，真 4K 0 条）—— 超分只能把 1080p 修得好看一点，
不能变出 4K。所以这里不假装，写清楚代价。

## 3. 音乐状态栏：换页保持最小态 + 更跟手

**「某些页面跳转后没保持最小态」的根因**：吸附态（`is-dock`，一枚封面圆）
是**刻意不落盘**的（R28 定的），`reflow()` 每次换页都按 `foldKey()` 重设；
而 `foldKey()` 在门与正站是**两把不同的键** —— 门上收成吸附态、点进正站读的是另一把，
读到的是更早的值，于是「换页之后弹回药丸」。

**修法**：
1. `writeFold()` **两把键一起写**，`prefFold()` 先读本上下文、再读另一把；
2. 拖到竖边松手时**落盘 `'2'`**（吸附态从此记住）；贴上下边落 `'1'`；
3. 跟手：**不再等 200ms 长按** —— 手指移动超过 8px 立刻开拖（`touch-action: none`
   本来就常设在卡片上，滚动不会被误伤）；
4. 磁性提示：拖动中离左右边 28px 内，卡片描边亮成朱红，松手吸到那一边
   （只提示，不抢位置 —— 中途把卡片从手指下面吸走反而更难放）。

## 4. 工具：「刷步数」→「帮您走走」，一人一个账号

### 4.1 改名与隐藏

- 「刷步数」→ **「帮您走走」**（工具目录卡、页面标题、三语文案同步）；
- **「步数管家」（`/bushu`）的入口从工具目录撤掉**（页面与接口都还在，卡密照旧能兑）。

### 4.2 登录用户自己的账号（`/tools/steps` 重写）

- 未登录：一句边界说明 + 「去登录」（`/login?next=/tools/steps`）；
- 登录后：保存**一个** Zepp Life 账号（`step_user` 表主键就是 `user_id`，
  再存就是覆盖 —— 「只能保存一个」写在表结构里，不靠接口自觉）、手动刷一次
  （可填目标步数，留空 = 10000–12000 随机）、「用上面填的账号临时刷」（不保存）、
  看**自己的**流水。
- **自动刷步在这页一个字都不显示** —— 站主要求只在后台可见。

### 4.3 自动规则改成 A / B / C / D

| 段 | 含义 | 字段 |
| :--- | :--- | :--- |
| **A** | 检测时刻（北京时间） | `beforeHour:beforeMinute` |
| **B** | 中间阈值 | `threshold` |
| **C** | 最终目标 | `toMin..toMax` 的中点（`targetOf`） |
| **D** | 随机幅度 | 区间的一半（`jitterOf`），实际提交 `C ± D` 内随机 |

**判据**（`evalBrush`）：**A 点之后**才评估（早于 A 不动手）。评估时先读今日步数：
① 读得到且已 ≥ C 的下限 → 跳过；② 读得到但不足 → 刷到 `C±D`（含 B ≤ 当前 < C 的补齐）；
③ **读不到** → **两段式**：先刷到 B 附近探路，成功了再补到 `C±D`。

两段式的理由：读不到步数与「真的没走」在日志里长得一模一样，直接刷 C 会把
「今天已经走了一万二」的人覆盖掉；先刷 B 再看返回，代价小得多。

`toMin/toMax` 仍是落库字段（`step_account` 表没有 target/jitter 两列，加列要动已有数据），
C 与 D 由这两个值反算，换算集中在 `putAccount` 一处。后台表单直接填 A/B/C/D 四个数。

## 6. 后台：栏目下拉白字 + 真正的实时编辑

### 6.1 下拉框「白显示」

`<select>` 本体吃 `.in` 的 `color: var(--ink)`（深色版次下接近白），而原生弹层是**浅色**的
（它不吃页面配色）→ 白底白字。修法两半：`color-scheme: light` 让 UA 用浅色弹层并自动配深字，
`option` 上再显式写一遍兜住不认 `color-scheme` 的国产内核。

### 6.2 实时内容层（`src/lib/live.ts` + `SITE` DO 三张表）

这一层是本轮唯一的新架构，先把它能做什么、不能做什么说清：

| 能力 | 做法 | 真的实时？ |
| :--- | :--- | :--- |
| **上传图片** | 浏览器先压到长边 1600px / WebP / q0.86 → base64 → `media` 表 → `/api/media/<key>` 直接吐字节（一年 immutable 缓存） | ✅ 上传完就能用 |
| **发布文章** | 写 `content_live` → Worker 用 `/live/<coll>/<slug>` 现渲染 Markdown | ✅ 点发布就能看，不用部署 |
| **分身知识库** | 写 `kb_live` → `loadKb()` 按 `question` 覆盖/追加静态那一份，缓存从 5 分钟降到 60 秒 | ✅ 一分钟内生效 |
| **列表页/归档页** | 仍是构建期产物 | ❌ 线上稿有自己的地址，但不进 `/posts` 列表 —— 那需要一次部署 |

Markdown 渲染器是**自写的子集**（标题/段落/粗斜体/行内码/围栏代码/列表/引用/链接/图片/分隔线），
不引第三方库：Worker 运行期不装依赖，引一个 remark 进来会把冷启动与包体积一起拉高。

后台「文章编辑」面板新增两颗键：**「发布到线上」**（`kb` 栏目走 `kb-live-put`，其余走
`content-live-put`）与 **「上传图片」**（选图 → 压 → 传 → 自动把 `![](...)` 插到光标处）。

## 8. 待沉麟决定

1. **线上稿要不要进列表** —— 现在它有地址、能被分享，但不进 `/posts`。
   要进就得让列表页也变成运行期渲染（或每次发布触发一次构建），那是另一个量级的改动。
2. **「观感增强」默认开还是关** —— 现在是开。它不改变分辨率，只是对比度/饱和度各提一点。
3. **D（随机幅度）默认 1000** —— 即 10000–12000。想要更窄就把 D 调小。
