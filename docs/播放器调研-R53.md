# 播放器调研与选择性采纳（R53）

> 沉麟的原话：「先优化播放吧，在播放页面能直接切换上下集，然后你再去 GitHub 上给我
> 仔细仔细调研一下线上播放器的一些优秀开源项目，都给我集合到我的网站中，要求对这些
> 都要有筛选性的集合，不要盲目集合。」
>
> 所以这份文档分两半：**已经落地的换集**，以及**逐个评估过的候选**。
> 结论一律带「采纳 / 不采纳 / 有条件采纳」，并写清代价 ——「不采纳」也是结论。

## 一、已经落地：播放页直接切上下集

**原状**：顶栏其实有 ⏮ ⏭，但手机上顶栏挤了标题、线路、画质、增强、倍速、上/下集、关闭
七样，那两颗只剩 1.9rem，基本摸不到；而且「这是第几集、还剩几集」页面上看不出来。

**现在**：

| 入口 | 行为 |
| :--- | :--- |
| 视频下方新增**换集栏** | 「‹ 上一集」+「第 3 / 40 集」+「下一集 ›」，第一集/最后一集自动置灰 |
| 键盘 | **← / →** 与 **P / N** 换集（capture 阶段拦掉原生「方向键快退/快进 5 秒」） |
| 顶部 ⏮ ⏭ | **删掉** —— 顶栏只留标题、线路、画质、增强、倍速、关闭，一个键只做一件事 |

**长按加速挪了位置**：原来「长按右箭头加速」和方向键换集冲突，现在
**长按倍速键 = 临时 3×，按住空格 = 临时 3×**，点按倍速键照旧轮换常驻倍速。
（长按松手用 `stopImmediatePropagation` 收尾，不会顺带轮换一次。）

手机端底栏两颗键 `flex: 1 1 0` 吃满宽度、字号提到 1rem —— 这是本轮唯一的体感重点。

## 二、调研：线上播放器开源项目全景

按「影响力 / 是否还在维护 / 与本站形态是否匹配」筛过一轮，只列真正值得看的。
星数是查证当时（2026-10-24）的 GitHub 数字。

| 项目 | ★ | 最近推送 | 它是什么 | 对本站的判断 |
| :--- | ---: | :--- | :--- | :--- |
| [videojs/video.js](https://github.com/videojs/video.js) | 40.0k | 2026-10-24 | 播放器框架（v10 起带 React），插件生态最大 | **不换内核**：价值在 UI 与插件，而本站播放器只有几百行、深度绑定「源→线路→剧集」，换上去等于重写接线；体积 +300KB 级 |
| [sampotts/plyr](https://github.com/sampotts/plyr) | 30.0k | 2026-10-21 | 极简 UI 层 | 同上，且**官方已宣布弃用**（转 Video.js 10）。不采纳 |
| [video-dev/hls.js](https://github.com/video-dev/hls.js) | 17.0k | 2026-10-24 | HLS 内核（MSE） | **本站正在用的就是它**（`public/tv/hls.min.js` = 1.7.3）。继续用 |
| [DIYgod/DPlayer](https://github.com/DIYgod/DPlayer) | 16.5k | 2026-03-04 | 带弹幕的播放器 | 弹幕不采纳（见第四节）；其余 UI 无不可替代之处 |
| [bytedance/xgplayer](https://github.com/bytedance/xgplayer) | 9.3k | 2026-10-23 | 字节的播放器，移动端手势做得好 | **借用交互思路**，不引框架。它的「倍速键长按」正是 R52/R53 那套手势的来源 |
| [shaka-project/shaka-player](https://github.com/shaka-project/shaka-player) | 8.3k | 2026-10-24 | DASH+HLS 双栈、DRM 完整 | 唯一「**有条件**」的引擎候选：将来要做 4K/HEVC/DRM 才划算。当前源池全是单码率 HLS，收益为 0 |
| [clappr/clappr](https://github.com/clappr/clappr) | 7.5k | 2026-10-23 | 插件化播放器 | 插件模型漂亮，但本站没有多租户插件需求。不采纳 |
| [zhw2590582/ArtPlayer](https://github.com/zhw2590582/ArtPlayer) | 4.1k | 2026-10-21 | 中文社区最活跃的「全能」播放器 | **借用交互与功能清单**（长按加速、字幕、快捷键、画中画、记忆播放），不整体引入 |
| [vidstack/player](https://github.com/vidstack/player) | 3.7k | 2026-10-07 | Web Component 播放器 | **已弃用**（转 Video.js 10）。不采纳 |
| [numberwolf/h265web.js](https://github.com/numberwolf/h265web.js) | 2.4k | 2026-10-13 | HEVC/H.265 软解（WASM） | **不采纳**：解码压在访客 CPU 上，中低端手机掉帧；本站源池没有 HEVC 源 |
| [oyuyue/nplayer](https://github.com/oyuyue/nplayer) | 1.4k | 2024-03 | 移动端优先、无运行时依赖 | 交互参照（移动端控制条）可用；一年多没更新，不引入 |
| [lid-labs/hevc.js](https://github.com/lid-labs/hevc.js) | 54 | 2026-10-23 | 给 hls.js/dash.js 用的 HEVC WASM 插件 | 同上，不采纳；有 HEVC 源之后才谈 |

**一句话结论**：`hls.js` 是这个生态里唯一「必须用」的那一层，本站已经在用；
其余项目提供的是 **UI 与交互范式**，值得「抄形状」而不是「装框架」。

## 三、筛选后的采纳清单（按性价比排序）

### P0 · 本轮已做

- [x] **播放页直接换集**：底栏一对大键 + 集数进度 + 键盘 ←/→、P/N；边缘自动置灰。
- [x] **一个键只做一件事**：顶部 ⏮⏭ 移除；长按加速挪到倍速键与空格。

### P1 · 建议下一轮做（成本都不大，收益直接可感）

| 项 | 抄自 | 做什么 | 代价 |
| :--- | :--- | :--- | :--- |
| **播放器内字幕** | ArtPlayer / NPlayer | 源给的 `.vtt/.srt` 直接挂；另允许拖一个本地字幕文件覆盖（`<track>`，一次会话有效） | ~120 行；SRT 转 VTT 格式极简，自己写 |
| **片头片尾标记** | ArtPlayer 的 highlight 插件 | 剧集条标出首尾集，进度条给「跳过片头」一颗键（默认 90 秒，可关） | ~60 行 |
| **画中画 + 系统媒体键** | 各家都有 | `requestPictureInPicture()` 一颗键；`navigator.mediaSession` 接播放/暂停/上下集，锁屏与耳机线控能用 | ~50 行，零依赖 |
| **续播浮层** | 本站已有续播 | 起播时若跳到 12:34，右上角提示「已从 12:34 继续 · 从头播」，点一下回 0 | ~30 行 |
| **手势：左右滑调进度、上下滑调音量** | NPlayer / xgplayer | 左右半屏滑动 seek、右侧上下滑音量，滑动时显示 HUD | ~150 行；要小心与原生控件抢手势 |

### P2 · 有条件再做

- **多码率自适应**：8 个源全是单变体播放列表，`levels` 永远只有 1 档 —— 逻辑已经写好了，
  但**没有源能喂它**。哪天真出现多码率源，它自动生效，不需要额外开发。
- **换内核到 Shaka**：只有「要做 4K/HEVC/DRM」时才划算。当前源池实测最高 1080p，换过去收益为 0，
  却要重写三级降级链（`direct → hlsProxy → fullProxy`）。
- **弹幕**：DPlayer 那套要配后端，本站是 Workers 免费档，写放大与审核成本都不低，而且没有弹幕源。

### 明确不采纳（写下来避免以后重提）

| 项 | 为什么 |
| :--- | :--- |
| 换整个播放器框架（Video.js / Plyr / Clappr / Vidstack） | 播放器与「源-线路-剧集」模型强耦合，换框架 = 重写接线 + 体积翻倍，收益只是「别人也在用」 |
| h265web.js / hevc.js 软解 | 中低端手机掉帧；源池没有 HEVC 源 |
| DRM / EME | 采集源没有 Widevine，做了也没内容可解 |
| AI 超分（MoonTVPlus 那套） | 逐帧 WASM/WebGL 推理，手机与免费档 Worker 都吃不消；且不能把 1080p 变成 4K |
| 弹幕 | 没有弹幕源、没有后端预算 |
