# 开发约定

沉麟的要求：**「把项目文件也整理好，不要污染本地文件开发环境，以后都这么做」**。
这份文档是这条要求的落地规则。

## 工作区卫生

### 项目目录里只放三类东西

1. **源码** —— `src/`、`public/`、根目录配置文件。
2. **文档** —— `docs/`、`README.md`。
3. **锁文件与版本约束** —— `package-lock.json`、`.nvmrc`。

其余一律不进项目目录。

### 临时文件一律放系统临时目录

调试网页抓取、试跑解析、临时脚本、下载的样本文件 —— 全部写到系统临时目录，
**不要落在项目里**，也不要图省事放桌面或用户根目录。

```bash
# Windows Git Bash 下项目外的临时目录
/c/Users/DUE/AppData/Local/Temp/
```

> **注意**：Git Bash 的虚拟 `/tmp` 在 Node 里会被解析成 `D:\tmp`，导致 `ENOENT`。
> Node 脚本要用 Windows 真实路径，或直接用管道传 stdin，不要依赖 `/tmp`。

用完即删。不要留着「以后可能有用」。

### 一次性脚本用完就删

`scripts/` 下只应存放**会重复使用**的脚本。一次性任务（生成占位图、批量改名、
数据迁移）跑完就删掉，需要时重写比读懂半年前的脚本更快。

`scripts/gen-placeholder-photos.mjs`（摄影栏目的一次性占位图生成脚本）**已删除**，
`scripts/` 空目录一并删除。删前确认过 `package.json` 里没有任何脚本引用它。

### 工具缓存目录

`.astro/`、`.wrangler/`、`dist/`、`node_modules/` 都是工具生成的，已在 `.gitignore` 中。
它们会被工具自己重建，可以随时删除。`.wrangler/tmp/` 尤其会堆积构建中间产物，
定期清理无副作用。

### `.gitignore` 覆盖清单

已覆盖：`dist/`、`.astro/`、`node_modules/`、各种 `*-debug.log`、`.env`、`.env.production`、
`.DS_Store`、`.idea/`、`.claude/`、`.wrangler/`。

**新增任何生成物或本地配置，先加 `.gitignore` 再生成。**

## 文档职责划分

README 只做入口，不承载细节。此前 6KB 的 README 混了上手、写作、部署、架构、待办
五种职责，需要哪一段都得通读 —— 这是要避免的反面样本。

| 文档 | 职责 | 什么时候改 |
| :--- | :--- | :--- |
| `README.md` | 项目速览 + 文档索引 | 新增文档，或项目定位变化 |
| `docs/需求台账.md` | 沉麟的原始需求、拆解、状态、验收判据 | 沉麟提新需求，或某项状态变化 |
| `docs/技术架构.md` | 选型理由、目录结构、设计系统、约束 | 引入新技术，或改动设计系统分层 |
| `docs/写作指南.md` | frontmatter 字段、栏目、Markdown 语法 | 内容模型（`content.config.ts`）变化 |
| `docs/部署运维.md` | Workers 配置、域名、发布流程、踩过的坑 | 域名变动，部署方式变化，踩到新坑 |
| `docs/开发约定.md` | 本文档 —— 工作区卫生与协作规则 | 沉麟提出新的工作方式要求 |
| `docs/AI版沉麟方案.md` | R6 的分阶段路线、选型、风险与待拍板问题 | R6 架构决策变化，或某阶段落地 |

**需求原文一律保留，不要转述。** 转述会丢约束 —— 「一点击就弹到添加好友页面」比
「加上社交链接」严格得多。

**踩过的坑必须记进文档**，写清「现象 → 根因」。同一个坑踩第二次是文档的失职。

## 提交规范

Conventional Commits：

```
feat|fix|docs|test|refactor|chore(scope): 描述
```

scope 用受影响的模块：`style`、`deploy`、`content`、`ui`、`docs`、`readme`。

**只在沉麟明确要求时提交。** 推送同理 —— 推送前必须问。

## 改动纪律

- 写入或覆盖文件前先读目标文件。
- 优先 `Edit` 定点替换，不整文件重写。
- 删除、`git push --force`、`reset --hard`、批量改动一律先问。
- 密钥只从环境变量读取，不写进代码、配置或日志，不在回复里回显。

### 新增带 JS 的页面：三条 SPA 规矩

**2026-08-22 起全站走 SPA 路由**（`BaseLayout.astro` 里的 `<ClientRouter />`），所以
页面脚本的写法变了。这三条不遵守的表现都是「首屏好的，导航过去就失效」，而且**不报错**：

1. **DOM 相关的绑定放进 `astro:page-load`**。bundled module script 全站只执行一次，
   顶层 `querySelector` 拿到的是首屏那份节点，导航后的新文档没被绑过。
   `astro:page-load` 首屏与每次导航都触发，包进去不影响首屏。
2. **`window` / `document` 上的监听必须留在模块顶层**。放进 `astro:page-load` 会每导航
   累积一层。要在导航后重取元素引用的，就只把「重取引用」这一步放进去。
3. **写在 `<html>` 上的运行期属性每次换页都会丢**（`swapRootAttributes` 先删光再套新文档的），
   要在 `astro:after-swap` 里补。已经这么做的：`ThemeBoot.astro`（`data-theme` / `data-js`）、
   `scripts/jukebox.ts`（`data-jk` / `--jk-room`）。

站内跳转用 `astro:transitions/client` 的 `navigate()`，**不要 `location.href = …`** ——
后者是硬导航，会把正在播的音频掐断。完整原理见
[技术架构 · 全站 SPA 路由](技术架构.md#全站-spa-路由与那个不会停的播放器)。

## 验证纪律

- 改了视觉，要在**深色和浅色两种模式下**都实际看过。浅色主题此前从未验证，
  正是因此才积压了「浅色下玻璃不明显」的问题。
- 改了内容模型，跑 `npm run build` 确认 schema 校验通过。
- 改了域名相关配置，**两个域名分别验证**。
- 改了 `/api/music/*` 或 `src/worker.ts`，要在 `npx wrangler dev` 上验 —— `astro dev`
  下这些路径必然 404，在那里「测不出问题」等于没测。
- **浏览器里复测样式改动前，先确认加载的是新文件。** `public/_headers` 给 HTML 配了
  `max-age=60, stale-while-revalidate=604800`，旧 HTML 会继续指向旧的哈希 CSS，
  表现成「改了没用」。破法：`fetch(url, { cache: 'reload' })` 逐个刷一遍再
  `location.replace()`；判据是浏览器实际加载的文件名与 `dist/` 里那个一致。
- 报告要忠实：跳过的步骤说跳过，失败的贴失败输出，不用「应该可以了」结束。
