# AI 版沉麟 —— 分阶段方案（R6）

> 这是**方案文档，不是施工单**。全文不含任何应立即执行的改动，`wrangler.toml` 一行未动。
> 沉麟第 5 轮定的是「R6 只出方案」，第 10 轮进一步定为「只写分阶段路线」。

需求原文与验收判据见 [需求台账 R6](需求台账.md#r6-接入-ai-版沉麟并实时监管-)。三条硬判据：

1. 访客能在站内与「AI 版沉麟」对话，回答风格取自沉麟的知识库；
2. 沉麟本人能**实时**看到访客与 AI 的对话；
3. 监管页受保护，访客不可见。

---

## 一、这件事最大的代价：单向门

站点现在是**纯 `[assets]`、没有 `main` 的静态资源 Worker** —— 没有一行服务端代码在运行。
要加对话接口，就必须在 `wrangler.toml` 里加：

```toml
main = "src/worker.ts"
```

加上这一行之后，本站的性质变了：

| | 现在 | 加了 `main` 之后 |
| :--- | :--- | :--- |
| 运行的代码 | 无 | 有服务端代码，每次请求都可能执行 |
| 出故障的面 | 只有构建期（构建失败＝不部署，线上不受影响） | 多了运行期（Worker 抛异常＝线上 500） |
| 需要担心的 | 无 | 冷启动、异常兜底、滥用、账单、访客数据 |
| 回退成本 | —— | 删掉 `main` 即可回到静态，但届时挂在上面的数据与路由要一并处置 |

**这是单向门**：不是不能回退，是回退后要清理的东西比现在多得多。所以这一行等沉麟明确批准
架构再加，不在实现阶段顺手加上。

顺带一个必须先确认的技术点：`_headers` 的自定义响应头**不作用于 Worker 生成的响应**
（官方文档确认："Custom headers are not applied to responses generated by your Worker code"）。
一旦有了 `main`，静态资源仍走 `_headers`，但 `/api/*` 这类动态响应的缓存头必须在 Worker
里自己设。这一点会影响 [边缘缓存](../public/_headers) 那套配置的适用范围，实现时要复查。

## 二、选型

全部用 Cloudflare 原生能力 —— 不引第三方密钥，不违反本站「不引用任何境外 CDN 资源」的硬约束
（推理走同源 `/api`，浏览器不直连任何第三方域）。

| 用途 | 选择 | 备选 / 说明 |
| :--- | :--- | :--- |
| 推理 | Workers AI（`env.AI` 绑定） | 免费档可用的模型有 `@cf/zai-org/glm-4.7-flash`、`@cf/google/gemma-4-26b-a4b-it`、`@cf/nvidia/nemotron-3-120b-a12b` 等（官方文档确认，2026-07-28 changelog）。**注意**：`kimi-k2.6`、`kimi-k2.7-code`、`glm-5.2`、`deepseek-v4-*` 已限定 Workers Paid，免费档调用返 403 |
| 知识库检索 | **AI Search**（Cloudflare 托管 RAG）优先 | 免费档 20,000 次查询/月、10 万文件/实例（官方文档确认）。自己拿 Vectorize＋切分＋embedding 手搓是同一件事的重活版，先试托管的 |
| 会话存储 | D1 | 免费档 5 GB 存储、读 500 万行/天、写 10 万行/天（官方文档确认）。对话记录是典型关系型数据，比 KV 合适 |
| 实时推送 | Durable Objects + WebSocket | 免费档**只能用 SQLite 存储后端**（官方文档确认）。一个会话一个 DO 实例，天然是「同一个对话的所有连接落在同一个地方」 |
| 监管页鉴权 | Cloudflare Access 优先，自建口令兜底 | 见下文风险 4 |

**为什么实时推送必须用 Durable Objects**：访客和沉麟是两条独立的 HTTP 连接，可能落在
不同的数据中心。普通 Worker 是无状态的，两边碰不到面。DO 提供「按 ID 寻址的唯一实例」，
把一个会话的访客连接与监管连接汇聚到同一个对象上，消息才能转发。这不是选型偏好，是这条
需求的必要条件。

## 三、四个阶段

每阶段都能独立停下来，且停下来时站点是可用状态。**不要跨阶段并行施工。**

### 阶段① 知识库的格式与灌入

先解决「AI 版沉麟说话像沉麟」这件事的输入端。没有这一步，后面三阶段做出来的是通用聊天机器人。

- 定知识库的存放形式。倾向复用现有内容集合：在 `src/content/` 下新开一个栏目（如 `kb/`），
  一条一个 Markdown，frontmatter 带 `question` / `topic` / `tags`。好处是写作流程与现在完全
  一致，走 Git，可版本控制，不需要额外后台。
- 定灌入方式：构建时导出成检索用的数据，或直接把 `kb/` 目录喂给 AI Search 的数据源。
- 定人格提示词（system prompt）的来源与版本管理 —— 它和知识库一样是会反复调的内容，
  应该在仓库里，不应该硬编码在代码里。

**验收判据**：知识库里有不少于 20 条真实问答；能在本地用一条命令（或 dashboard）确认检索
返回的是相关条目，而不是随机片段。此阶段**站点无任何变化**，`wrangler.toml` 仍不动。

### 阶段② 只读问答（第一次引入服务端代码）

- 加 `main = "src/worker.ts"`，只实现一条 `POST /api/chat`：接收问题 → 检索知识库 →
  调 Workers AI → 返回答案。**不落库、不记录、无状态。**
- 前端一个最小对话框。按本站「杂志式极简」的中心设计理念，不做打字机动画、不做头像气泡，
  一问一答的纯文本流。
- 必须有的兜底：模型超时／超额（429、错误码 3036）／检索为空，三种情况都返回一句人话，
  不把原始错误抛给访客，也不让页面卡死。

**验收判据**：站上能问答；断开 AI 绑定或人为触发 429 时页面显示友好提示而非 500；
静态页面（首页、文章等）的响应头与加 `main` 之前**逐字相同**（用 `curl -I` 对比，
证明没有把静态资源的行为带坏）。

### 阶段③ 会话落库

- D1 建表：会话表 + 消息表。消息记 `session_id` / `role` / `content` / `created_at`。
- `POST /api/chat` 改为写入后再回答。
- **这一步开始就有访客数据了**，隐私边界必须同时落地，不能留到阶段④（见风险 3）。

**验收判据**：一次对话完整落库，字段可查；写入失败不阻塞回答（降级为不记录，而不是报错）；
站上有明确告知「本对话会被站长看到」。

### 阶段④ 实时监管页与鉴权

- Durable Object：一个会话一个实例，持有访客侧与监管侧的 WebSocket，转发消息。
- `/admin`：列出进行中的会话，点进去实时看消息流。
- 鉴权先行 —— **`/admin` 在第一次能访问之前就必须是受保护的**，不允许「先做功能后加锁」。

**验收判据**：两台设备（一台当访客、一台当沉麟）同时在线，访客发一句，监管页在 2 秒内
出现同一句；未鉴权直接访问 `/admin` 返 401/403 或跳登录，且**不泄漏任何会话内容**；
断线重连后消息不丢、不重复。

## 四、风险清单

### 1. 免费额度会被穿透，而且是「静默降级」而不是「账单爆炸」

免费档超限的行为是**后续操作直接失败**（Workers AI 返 429 / 错误码 3036；D1 返明确的
超限文案；DO 超限亦为操作失败），每天 00:00 UTC 重置。也就是说：不会突然收到大额账单，
但站点会在某个下午突然「AI 不理人了」。

- Workers AI：10,000 Neurons/天。超出需 Workers Paid（起价 $5/月，含同样的 10,000/天，
  超出按 $0.011/1,000 Neurons）。**一次对话消耗多少 Neurons 取决于模型与 token 数，
  未核实，必须在阶段②实测后才能估算「每天能撑多少次对话」。**
- D1：写 10 万行/天。按一次对话写 2 行算，理论上够用，但见风险 2。
- 必须做的：额度耗尽时前端显示「今天的对话额度用完了，明天再来」，而不是报错。

### 2. 防刷量

一个公开的、无需登录的推理接口，等于把免费额度挂在公网上。**必须在阶段②就有限流，
不能等被刷了再加。**

可选手段：Worker 里按 IP + DO 计数做滑动窗口；Cloudflare 的 Rate Limiting 规则；
两者叠加。具体选择等阶段②实测单次消耗后再定 —— 限流阈值必须由实测数字推出来，
不能凭感觉写一个数。

### 3. 访客输入即入库的隐私边界（这条最需要沉麟本人拍板）

需求原文是「我能实时的监管并能看到实时的聊天信息」—— 这意味着**访客打的每一个字都会被
第三人看到并存下来**。这不是技术问题，是需要明说的产品决定：

- 对话框旁必须有一句显式告知（拟：「这里的对话站长可以看到」）。藏起来这件事，
  是拿访客的信任换功能。
- 存多久？建议定一个保留期（如 30 天）并在阶段③就写好清理逻辑，而不是无限期堆着。
- 存不存 IP？建议**不存**。要区分会话用随机 session id 就够，IP 是纯负担。
- 谁能看？只有沉麟。这一条靠阶段④的鉴权保证。

**需要沉麟明确回答的**：告知文案怎么写、保留期多久、是否存 IP。

### 4. 鉴权方式二选一

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| Cloudflare Access | 不用自己写登录、不用存密码、支持邮箱一次性验证码；Worker 侧只需校验 Access 注入的 JWT | 要开 Zero Trust；**免费档包含多少席位未核实**，落地前必须先查清楚，别做完才发现要付费 |
| 自建口令 | 零外部依赖，一个环境变量搞定 | 密码轮换、暴力破解、会话保持全要自己写；一旦写错就是「监管页被人翻了」 |

倾向 Cloudflare Access —— 自建口令保护的是**别人的聊天记录**，这类东西自己写登录的性价比
很差。但席位数必须先核实。

按本站约定，口令／密钥一律只从环境变量读取，不写进代码、配置或日志。

### 5. 一个容易被忽略的：AI 会替沉麟说错话

「AI 版沉麟」用第一人称回答，访客会当成沉麟本人的观点。知识库覆盖不到的问题上，模型会
一本正经地编。

- 检索为空时不要硬答，回一句「这个我没写过」。
- 页面上标明这是 AI，不是本人实时回复。
