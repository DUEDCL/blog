## 一、这件事最大的代价：单向门（**已经走过去了**）

> **2026-08-22 更新**：这道门已经开了，但不是被本方案开的 —— 是
> [R11 点歌台](需求台账.md#r11-点歌台-) 开的。点歌绕不开服务端（上游 `api.php` 无 CORS、
> 证书过期只剩 http，浏览器不可能直连），所以 `main = "src/worker.ts"` 提前落地。
> 本节下面那张对照表描述的「加了 `main` 之后」，**现在是本站的现状**。

站点原先是**纯 `[assets]`、没有 `main` 的静态资源 Worker** —— 没有一行服务端代码在运行。
要加对话接口，就必须在 `wrangler.toml` 里加：

```toml
main = "src/worker.ts"
```

加上这一行之后，本站的性质变了：

| | 加 `main` 之前 | 加了 `main` 之后（＝现状） |
| :--- | :--- | :--- |
| 运行的代码 | 无 | 有服务端代码，每次请求都可能执行 |
| 出故障的面 | 只有构建期（构建失败＝不部署，线上不受影响） | 多了运行期（Worker 抛异常＝线上 500） |
| 需要担心的 | 无 | 冷启动、异常兜底、滥用、账单、访客数据 |
| 回退成本 | —— | 删掉 `main` 即可回到静态，但届时挂在上面的数据与路由要一并处置 |

**这是单向门**：不是不能回退，是回退后要清理的东西比现在多得多。**第 11 轮已批准走这道门**，
2026-08-22 由点歌台实际走完。原先写在这里的「加 `main` 是阶段②的第一个动作，阶段①结束前
`wrangler.toml` 一行不动」**已被推翻** —— 阶段①（知识库定稿）尚未完成，`wrangler.toml` 已改。
现存的 `src/worker.ts` 只有 `/api/music/*` 四条只读 GET，其余路径一律
`return env.ASSETS.fetch(request)` 交回静态资源。

顺带那个原先标着「实现时要复查」的技术点**已确认并已落地**：`_headers` 的自定义响应头
**不作用于 Worker 生成的响应**（官方文档确认："Custom headers are not applied to responses
generated by your Worker code"）。静态资源仍走 [`_headers`](../public/_headers)，而
`/api/music/*` 的缓存头是在 `src/worker.ts` 里逐端点自己设的（`list` 3600、`search` 300、
`lyric` 86400、`url` 与任何失败 `no-store`），并全部带 `X-Robots-Tag: noindex`。
阶段②的 `/api/chat` 照同一个办法处理，不要指望 `_headers`。

## 二、选型

全部用 Cloudflare 原生能力 —— 不引第三方密钥，不违反本站「不引用任何境外 CDN 资源」的硬约束
（推理走同源 `/api`，浏览器不直连任何第三方域）。

| 用途 | 选择 | 备选 / 说明 |
| :--- | :--- | :--- |
| 推理 | Workers AI（`env.AI` 绑定） | 免费档可用的模型有 `@cf/zai-org/glm-4.7-flash`、`@cf/google/gemma-4-26b-a4b-it`、`@cf/nvidia/nemotron-3-120b-a12b` 等（官方文档确认，2026-07-28 changelog）。**注意**：`kimi-k2.6`、`kimi-k2.7-code`、`glm-5.2`、`deepseek-v4-*` 已限定 Workers Paid，免费档调用返 403 |
| 知识库检索 | **AI Search**（Cloudflare 托管 RAG）优先 | 免费档 20,000 次查询/月、10 万文件/实例（官方文档确认）。自己拿 Vectorize＋切分＋embedding 手搓是同一件事的重活版，先试托管的 |
| 会话存储 | **不存**（第 11 轮决议） | 原计划 D1 建会话表＋消息表。拍板结果是对话只实时转发、**不落库**，所以 **D1 不建**。这条决议同时砍掉了一整个阶段，见风险 3 |
| 实时推送 | Durable Objects + WebSocket | 免费档**只能用 SQLite 存储后端**（官方文档确认）。一个会话一个 DO 实例，天然是「同一个对话的所有连接落在同一个地方」 |
| 监管页鉴权 | **Cloudflare Access**（第 11 轮定） | 免费档「$0 forever，best for teams under 50 users」，沉麟只需 1 席（官方定价页确认）。见风险 4 |

**为什么实时推送必须用 Durable Objects**：访客和沉麟是两条独立的 HTTP 连接，可能落在
不同的数据中心。普通 Worker 是无状态的，两边碰不到面。DO 提供「按 ID 寻址的唯一实例」，
把一个会话的访客连接与监管连接汇聚到同一个对象上，消息才能转发。这不是选型偏好，是这条
需求的必要条件。

## 三、三个阶段

每阶段都能独立停下来，且停下来时站点是可用状态。**不要跨阶段并行施工。**

> 原方案是四阶段。第 11 轮「对话不落库」的决议砍掉了原阶段③（会话落库），
> 原阶段④（实时监管页与鉴权）顺位成阶段③。

### 阶段① 知识库的格式与灌入 🚧

先解决「AI 版沉麟说话像沉麟」这件事的输入端。没有这一步，后面两阶段做出来的是通用聊天机器人。

**已定并落地**：存放形式走 `src/content/kb/`，一条一个 Markdown，复用现有内容集合机制
（`src/content.config.ts` 的 `kb` 集合）。走 Git、可版本控制、写作流程与写文章完全一致，
不需要额外后台。frontmatter 四个字段：

| 字段 | 必填 | 作用 |
| :--- | :--- | :--- |
| `question` | 是 | 主问题。按访客真会怎么问来写，不是文章标题 |
| `aliases` | 否（默认 `[]`） | 同一件事的其他问法。检索靠语义相似度，问法给得越多命中越稳 |
| `topic` | 否 | 分类，自己整理用，不参与检索 |
| `draft` | 否（默认 `false`） | `true` 表示未定稿，不进知识库 |

正文就是答案，**用第一人称写** —— 检索命中后正文原样喂给模型当回答依据，写的时候就当是
在直接回答访客。

这个集合**刻意不生成任何页面**，也不进归档与标签索引：`utils/content.ts` 的 `Section` 与
`getAllEntries()` 都是硬编码的四个栏目。已实测确认加 `kb` 后仍是 16 页，且用「故意写坏
frontmatter → 构建必须失败」证明了文件真的被读到（不是 glob 静默跳过）。

**仍待定**（等知识库有内容后再决，避免拿 1 条样本去调检索）：

- 灌入方式：构建时导出成检索用数据，或直接把 `kb/` 目录喂给 AI Search 的数据源。
- 人格提示词（system prompt）的来源与版本管理 —— 它和知识库一样是会反复调的内容，
  应该在仓库里，不应该硬编码在代码里。

**验收判据**：知识库里有不少于 20 条真实问答；能在本地用一条命令（或 dashboard）确认检索
返回的是相关条目，而不是随机片段。此阶段**站点无任何变化** —— 原文还写着「`wrangler.toml`
仍不动」，那句已被 R11 点歌台推翻（`main` 已加），但**知识库这一阶段自己确实不需要动它**。

**当前进度（2026-08-20 第 11 轮）**：集合已建，**24 条骨架已就位，但全部 `draft: true`，
定稿 0 条**。骨架不满足验收判据 —— 判据要的是「真实问答」，`draft: true` 的条目不进知识库。

按「谁能写」分三批：

| 批次 | 条数 | 状态 | 沉麟要做什么 |
| :--- | :--- | :--- | :--- |
| **A 技术类**（`why-static` / `why-workers-not-pages` / `why-no-foreign-cdn` / `two-domains` / `how-i-publish` / `glass-design` / `why-so-few-things` / `site-speed` / `site-stack`） | 9 | 正文已写，事实全部核对自本仓库 docs | **只改口吻**，然后去掉 `draft` |
| **B 关于你本人**（`who-am-i` / `what-i-do` / `where-i-live` / `how-to-reach-me` / `why-i-blog` / `how-i-learn` / `my-toolchain` / `what-im-learning` / `my-projects` / `view-on-ai` / `my-interests` / `nickname-chenlin`） | 12 | 只有 frontmatter，正文是「要答什么」的提示 | **写正文**，删掉提示引用块 |
| **C 元问题**（`are-you-real` / `is-chat-private` / `is-code-open`） | 3 | 正文已写（答案由架构决议决定，不是个人观点） | **确认口径**即可，各条末尾标了待确认点 |

批 A 的正文我能写，是因为那些答案是仓库里的可核对事实（选型理由、踩过的坑、实测数字）；
批 B 的正文我写不了，写了就是编。批 C 的三条里，`is-code-open` 原本卡着一个决定，
**第 11 轮已定：代码公开**（落地为新建 `DUEDCL/blog` 公开、原仓库保持私有，原因见
[部署运维 · 仓库公开前的脱敏](部署运维.md#仓库公开前的脱敏)），该条正文已按公开事实
改写，现在只剩改口吻。

**已实测确认**（2026-08-20）：24 条全部通过 schema 校验，构建仍是 16 页（不产页面、不进
归档与标签索引）。并用「临时写一个缺 `question` 的探针文件 → 构建必须失败」再次证明 glob
真的读到了这批新文件，报错为 `InvalidContentEntryDataError: kb → _probe ... question: Required`，
探针已删除、构建恢复 16 页。

**距判据还差**：≥20 条定稿。批 A 改口吻 + 批 C 确认口径就能凑到 12 条，剩下 8 条必须从
批 B 里出 —— 也就是说**这件事最终绕不开你写关于自己的答案**。


### 阶段② 只读问答（在已有 Worker 上加 `/api/chat`）

> 原标题是「第一次引入服务端代码」。**已经不是第一次了** —— R11 点歌台已经建好
> `src/worker.ts` 并加了 `main`，所以这一阶段是在既有 Worker 上加一条路由，
> 「引入运行期」这半边代价不用再付一次。

- 在 `src/worker.ts` 里加一条 `POST /api/chat`：接收问题 → 检索知识库 → 调 Workers AI →
  返回答案。**不落库、不记录、无状态。** 缓存头照点歌台的办法在代码里自己设（`_headers`
  管不到 Worker 响应），`/api/chat` 应当是 `no-store`。
- 顺手要做的一件事：`wrangler.toml` 的 `run_worker_first` 现在是 `[ "/api/music/*" ]`，
  加 chat 时要把 `/api/chat` 一并列进去。
- 前端一个最小对话框。按本站「杂志式极简」的中心设计理念，不做打字机动画、不做头像气泡，
  一问一答的纯文本流。
- 必须有的兜底：模型超时／超额（429、错误码 3036）／检索为空，三种情况都返回一句人话，
  不把原始错误抛给访客，也不让页面卡死。

**验收判据**：站上能问答；断开 AI 绑定或人为触发 429 时页面显示友好提示而非 500；
静态页面（首页、文章等）的响应头与加 `/api/chat` 之前**逐字相同**（用 `curl -I` 对比，
证明没有把静态资源的行为带坏 —— 基线现在是「已有点歌台的那版 Worker」，不再是纯静态）。

### 阶段③ 实时监管页与鉴权

- Durable Object：一个会话一个实例，持有访客侧与监管侧的 WebSocket，转发消息。
  **消息过完即弃** —— 只在内存里转发，不写 DO 的 SQLite 持久化对话内容。
- `/admin`：列出**当前在线**的会话，点进去实时看消息流。注意「当前在线」是不落库的直接
  后果 —— **沉麟不在线时发生的对话，事后无从查看**。这是第 11 轮决议的代价，需求原文只要
  「实时监管」，所以判定为可接受；哪天想要历史记录，就得把原阶段③（落库）重新捡回来。
- 鉴权先行 —— **`/admin` 在第一次能访问之前就必须是受保护的**，不允许「先做功能后加锁」。
  走 Cloudflare Access，Worker 侧只校验 Access 注入的 JWT。
- 访客侧必须同时上「这里的对话站长可以看到」的告知（见风险 3）。

**验收判据**：两台设备（一台当访客、一台当沉麟）同时在线，访客发一句，监管页在 2 秒内
出现同一句；未鉴权直接访问 `/admin` 返 401/403 或跳登录，且**不泄漏任何会话内容**；
断线重连后消息不丢、不重复；站上有明确告知「本对话站长可以看到」。

## 四、风险清单

### 1. 免费额度会被穿透，而且是「静默降级」而不是「账单爆炸」

免费档超限的行为是**后续操作直接失败**（Workers AI 返 429 / 错误码 3036；DO 超限亦为操作
失败），每天 00:00 UTC 重置。也就是说：不会突然收到大额账单，但站点会在某个下午突然
「AI 不理人了」。

- Workers AI：10,000 Neurons/天。超出需 Workers Paid（起价 $5/月，含同样的 10,000/天，
  超出按 $0.011/1,000 Neurons）。**一次对话消耗多少 Neurons 取决于模型与 token 数，
  未核实，必须在阶段②实测后才能估算「每天能撑多少次对话」。**
- ~~D1：写 10 万行/天。~~ 不落库，无此项（第 11 轮决议）。
- AI Search：20,000 次查询/月。按一次对话一次检索算，够用，但同样挂在公网上，见风险 2。
- 必须做的：额度耗尽时前端显示「今天的对话额度用完了，明天再来」，而不是报错。

### 2. 防刷量

一个公开的、无需登录的推理接口，等于把免费额度挂在公网上。**必须在阶段②就有限流，
不能等被刷了再加。**

可选手段：Worker 里按 IP + DO 计数做滑动窗口；Cloudflare 的 Rate Limiting 规则；
两者叠加。具体选择等阶段②实测单次消耗后再定 —— 限流阈值必须由实测数字推出来，
不能凭感觉写一个数。

### 3. 访客对话被第三人实时旁听的隐私边界

> 第 11 轮已拍板：**不落库**。原「访客输入即入库」的风险面因此大幅缩小 —— 没有数据库，
> 就没有保留期、没有清理逻辑、没有「被拖库」这回事。保留期与是否存 IP 两问随之消失。

**但没消失的那一半**：需求原文是「我能实时的监管并能看到实时的聊天信息」，这意味着
**访客打的每一个字都会被第三人实时看到**。不存，不等于不被看。这不是技术问题，是必须
明说的产品决定：

- 对话框旁必须有一句显式告知（拟：「这里的对话站长可以看到」）。藏起来这件事，
  是拿访客的信任换功能。
- 存多久？—— **不存**，无此问题。DO 只在内存里转发，连接断开即消失。
- 存不存 IP？—— **不存**。区分会话用随机 session id 就够，IP 是纯负担。
- 谁能看？只有沉麟。这一条靠阶段③的 Cloudflare Access 鉴权保证。

**仍需沉麟明确回答的**：告知文案怎么写（拟稿见上，可改）。这是本条唯一的未决项。

### 4. 鉴权：走 Cloudflare Access（第 11 轮已定）

席位数已核实 —— 官方定价页：Free Plan「**$0 forever**，best for teams under 50 users」，
沉麟只需 1 席，免费档够用。原先标着「未核实」的阻塞点已结清。

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| **Cloudflare Access（已选）** | 不用自己写登录、不用存密码、支持邮箱一次性验证码；Worker 侧只需校验 Access 注入的 JWT | 要开 Zero Trust |
| ~~自建口令~~（未选） | 零外部依赖，一个环境变量搞定 | 密码轮换、暴力破解、会话保持全要自己写；一旦写错就是「监管页被人翻了」 |

选 Access 的理由：自建口令保护的是**别人的聊天记录**，这类东西自己写登录的性价比很差。

按本站约定，口令／密钥一律只从环境变量读取，不写进代码、配置或日志。

### 5. 一个容易被忽略的：AI 会替沉麟说错话

「AI 版沉麟」用第一人称回答，访客会当成沉麟本人的观点。知识库覆盖不到的问题上，模型会
一本正经地编。

- 检索为空时不要硬答，回一句「这个我没写过」。
- 页面上标明这是 AI，不是本人实时回复。
