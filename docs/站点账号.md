# 站点账号（邀请码登录）

> 2026-10-20 上线。对应提交 `d1d18e2`（主体）、`1b9f77db`（后台分区）、
> `972b1b0f`（顶栏登录态）。
>
> 一句话：**站点从「谁都能用」变成「登录才能用工具与分身」**，注册靠站主手动发的邀请码。

## 一、改了什么范围（这是最容易记错的一条）

站主的原话是「将本站做成登录式的吧」，紧接着限定「普通访客不能使用工具页面的东西和
『问沉麟的分身』」。两句范围不一样，**最终按后者执行**：

| 路径 | 未登录 | 说明 |
| :--- | :--- | :--- |
| `/tools`、`/tools/*` | **302 → `/login?next=`** | 工具页 |
| `/tv`、`/tv/`、`/tv/index.html` | **302 → `/login?next=`** | 影视聚合 |
| `/api/chat` | **401 JSON** | 「问沉麟的分身」 |
| `/api/tv/hist` | **401 JSON** | 每用户影视记录 |
| `/`、文章、随笔、作品、音乐、图库、`/music/` | 200 公开 | 内容不拦，SEO 与老读者不受影响 |
| `/tv/app.js`、`/tv/hls.min.js` | 200 公开 | **静态资源绝不能拦**，否则页面引不到脚本 |
| `/bushu`、`/api/app/*` | 200 | **不拦**：它自己有 `bs_sess` 登录 + 卡密体系，再套一层是双重登录 |
| `/admin`、`/api/admin/*` | 200 | **不拦**：后台自己一套口令。这也是兜底 —— 站长永远进得去生成第一个邀请码 |

判定只有一处：`src/lib/site-api.ts` 的 `needsLogin(pathname)`。要改范围就改它，别在
worker 里散着写。

## 二、为什么另开一个 `SiteDB`

`AppDB` 里已经有 `user` / `session` / `card`（卡密）三张表，看起来可以直接复用。
**没有复用**，理由是：

1. `AppDB` 是**步数管家（多用户商用版）**的库，`user` 绑着 Zepp 账号、`card` 绑着 VIP 天数。
   站点账号混进去，等于让「改站点登录」有机会动到一门生意的用户表。
2. 两套账号的语义不同：步数管家是「买卡密 → 绑 Zepp」，站点是「邀请码 → 一个身份」。
3. 一个业务一个库，是 `docs/技术架构.md` 里既有的约定（R48 定下的）。

所以：`src/site-db.ts`，单实例 `idFromName('site')`。
**单实例是有意的** —— 「账号唯一」和「邀请码原子占用」必须在同一个串行语义里才成立。

## 三、五张表

```sql
site_user    (id, account UNIQUE, nick, pass_hash, created_at, last_login_at, status, invite)
site_session (token_hash PK, user_id, created_at, expires_at)
invite       (code PK, max_uses, used_count, expires_at, note, created_at, status)
tv_q         (user_id, q, ts, PRIMARY KEY(user_id, q))
tv_prog      (user_id, k, ..., PRIMARY KEY(user_id, k))
```

- `pass_hash` 存 `pbkdf2$<迭代>$<saltB64>$<hashB64>`，**明文口令不落库、不进日志、不进报错**。
- `site_session` 存的是 **token 的 SHA-256 摘要**，不是 token 本身 —— 库被读走也登不进任何人的号。
- 停用一个账号会**顺手删掉它的所有会话**（`/user-set-status`），否则「已停用但还能用」。

## 四、邀请码的语义（站主要求「手动创建，有效期与次数可编辑」）

| 字段 | 取值 | 含义 |
| :--- | :--- | :--- |
| `max_uses` | `0` | 不限次数 |
| | `n > 0` | 最多能被 n 个人用来注册 |
| `expires_at` | `0` | 永不过期 |
| | 时间戳 | 到点失效 |
| `used_count` | — | 已成功注册的人数，可被站长**手动清零**以复用同一个码 |
| `status` | `1` / `0` | 启用 / 作废（作废不删记录，事后能查） |

码的字母表是 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（去掉 `0/O/1/I/L`，念出来不会混），
长度 10。

### 4.1 占用必须是原子的

```
错：SELECT used_count → 判断 → UPDATE
对：UPDATE invite SET used_count = used_count + 1
    WHERE code = ? AND status = 1
      AND (max_uses = 0 OR used_count < max_uses)
      AND (expires_at = 0 OR expires_at > ?)
    然后看 rowsWritten 是否 === 1
```

先查后改的写法在并发下会让**一个码开出两个号**。带条件的 UPDATE + 判影响行数，
配合 DO 的串行执行，才能保证不会。验证里专门测了这条（同码二次注册被拒）。

## 五、认证实现

参照 `src/app.ts`（步数管家）的既有做法，参数刻意一致：

- **口令**：PBKDF2-SHA256，20000 次。为什么不是 OWASP 建议的几十万？Workers Free 是
  10 ms CPU/请求，每次登录要做一次派生；而这个哈希不落明文、不进仓库，离线爆破的前提不成立
  —— 与 `ADMIN_HASH` 那条注释是同一个取舍。
- **会话**：`crypto.getRandomValues(32 字节)` → base64 去符号 → 只把 token 给浏览器，
  库里存 `sha256(token)`。有效期 30 天。
- **cookie**：`dl_sess`，`HttpOnly` + `SameSite=Lax` + `Path=/`，https 下自动加 `Secure`。
- **登录失败**：统一回「账号或密码不对」，且**固定等 600 ms**。
  不区分「没这个号」和「密码错」，否则接口就是个账号枚举器；固定延迟还顺手给短口令买了时间。

## 六、后台怎么用

`/admin` → 顶部 tab「站点账号」：

1. **生成**：数量（1~50）/ 可用次数 / 有效天数 / 备注。天数填 0 = 永不过期。
2. **逐条编辑**：改次数、改有效期（从今天起 n 天，0 = 永久）、改备注、
   **已用清零**（让同一个码再注册一次）、作废、删除。
3. **用户列表**：账号 / 昵称 / 注册时间 / 上次登录 / 记录条数 / 该用户用的哪个码；
   右侧一枚按钮停用或启用。

> 编辑入口用的是 `prompt()`。这是刻意的取舍：这一版的目标是「站长能自己改」，
> 一个 prompt 换一行代码；真要频繁改再换成行内输入框。

## 七、每用户的影视记录

`GET /api/tv/hist` 取回该用户全部记录，`POST /api/tv/hist` 写一条（`{q}` 或 `{prog:{…}}`）。
**必须登录**，没有「匿名也能写」的兜底。

前端（`public/tv/app.js`）的策略：

1. 页面初始化后请求一次 `/hist`；**401 就静默跳过**，匿名照旧用 localStorage。
2. 登录用户：把云端记录与本地合并 —— 搜索历史按关键词去重、按时间排序取前 30；
   播放进度按 `ts` 取较新的那条。
3. 之后**双写**：本地照旧写（离线可用），同时 POST 到云端。
4. 于是「继续观看」和断点续播跨设备可用。

上限：搜索 30 条、进度 60 条（DO 里写记录时顺手删多余的）。

## 八、首次上线的顺序（别搞反）

1. 部署完**先别急着让任何人用**。
2. 打开 `/admin`（口令是原来那个）→「站点账号」→ 生成一个邀请码。
3. 打开 `/login` → 用这个码注册自己的账号。
4. 之后 `/tools` 与 `/tv` 才进得去。

**`/admin` 不在拦截名单里**，就是这个顺序的保险：哪怕一个邀请码都还没发，站长也永远进得去。

## 九、怎么验（当时的实测清单）

本地 `npx wrangler dev`，用 `--var` 把 `ADMIN_HASH` 覆盖成测试口令，
**不碰线上后台口令**：

- 认证与邀请码 **16/16**：后台登录、生成 2 码、字段齐全、注册成功、会话可用、
  同码二次注册被拒、未登录 302 / 已登录 200、未登录 chat 401 / 已登录不再 401、
  改次数后同码可再注册、过期码被拒、用户列表、停用后会话失效。
- 记录与隔离 **9/9**：未登录 401、登录、写两条搜索 + 一条进度、读回、
  重写不重复、**另一个账号看不到别人的记录**。

线上另核了准入：`/tools/` `/tv` `/api/chat` 按预期拦截；`/tv/app.js`、`/`、`/music/` 正常 200。

## 十、已知限制（先记下来，别当成 bug 反复查）

1. **没有找回密码**。忘密码只能站长在后台停用后重发邀请码。
2. **没有登录限流**（失败计数、锁定）。现在只靠 600 ms 固定延迟顶着；
   真要挡得加状态，等有需要再说。
3. **邀请码泄漏 = 别人能注册**。作废即可，但已注册的账号要单独停用。
4. **记录合并是「按时间戳取新」**，没有冲突解决。两台设备同时看到同一集时，
   后写的覆盖先写的；对个人站够用。
5. **账号没有邮箱**，所以无法做「忘记密码 → 邮件重置」。
